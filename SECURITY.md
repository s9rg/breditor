# Security reporting

Use the repository's [private vulnerability report form](https://github.com/s9rg/breditor/security/advisories/new)
for potential vulnerabilities in the editor, package artifacts, reference relay,
or release process. For usage questions and ordinary bug reports, use
[GitHub Issues](https://github.com/s9rg/breditor/issues).

Include the source commit or package version, affected entry point, environment,
and expected impact. A small synthetic document or a redacted log can help
maintainers reproduce a report. Keep user documents, credentials, access tokens,
and production backups out of reports and attachments.

Repository maintainers triage reports in GitHub Security Advisories. They
identify the affected package and runtime versions, coordinate any dependency
update with upstream maintainers, and use the advisory to communicate the fix
and upgrade instructions.
