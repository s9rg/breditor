Disposable real Rust/Wasm editor. Nothing is saved; reload resets the sample. Use non-sensitive test text. Your Copy and Cut commands replace the system clipboard. This page never calls clipboard APIs on its own.

Reports contain bounded event metadata, owner status/revision, browser details and the candidate Wasm hash—not document, clipboard, scratch or input contents. Inspect the report before sharing it.

Manual checks in Safari and Chrome

  1. Select “Collect your ideas” in the first bullet. Use native Copy and paste into the scratch area. Confirm the exact text, without a bullet marker.
  2. Select the same text and use native Cut. Confirm one deletion, then paste outside the editor. Undo once to restore the bullet text exactly.
  3. Move the caret to the end of the numbered item “Write a first draft”. Type “!” immediately; Undo and Redo once. Confirm the caret and numbering remain correct.
  4. Native Paste at that caret should insert the copied text once, without importing list structure. Undo once. Repeat Copy/Cut across both numbered items: plain text should contain a newline, and Undo must restore both items with numbering starting at 3. Try both selection directions.
  5. Select the first heading. Apply a different heading rank, Bullet list, Numbered list and Remove list. Undo/Redo each operation and confirm its text and heading rank survive. Apply a Link, then Undo/Redo its value.
  6. Confirm each check below only after observing it. Composition events alone do not qualify an OS input method, and automated accessibility checks do not qualify a screen reader. Test those separately in the main demo.
Separate OS input and screen-reader checks

These checks require a person using the Mac's keyboard. A settings switch, accessible page tree, or trusted event alone is not proof. The clipboard checklist and report do not certify either check.

Input method: establish a control first

  1. Record the browser version, input source and fixture Wasm hash from the report. Note original system settings before changing them.
  2. Select Japanese–Romaji (or the input method under test). In the scratch area above, compose and commit a short non-sensitive word. Confirm an actual candidate/preedit interaction and the intended committed text. If only literal Latin keys appear, stop: IME activation is unverified.
  3. Repeat inside the heading, a bullet item and a numbered item. Confirm one committed insertion, unchanged surrounding text and numbering, then one Undo and one Redo restoring the exact before/after states.
  4. Start another composition and cancel it using the input method's cancel command. Confirm the original text and caret return and no extra history entry appears. Use the main demo separately for commit/reload/recovery.

Screen reader: establish audible navigation first

  1. Enable VoiceOver and confirm spoken navigation in the browser's own controls before entering the editor. If speech or the VoiceOver cursor cannot be observed, stop and record the check as unverified.
  2. Navigate to the editor and toolbar. Check their announced names, heading ranks, list boundaries/items, button names and pressed/disabled states. Enter editing, move/select text, and verify the announced selection.
  3. Apply a heading/list change, Undo and Redo. Open Link, edit its URL, then close with Escape. Confirm usable focus returns and text is preserved. Compare what is spoken with what actually changed.

Record exact observations and failures separately; never infer a pass from this page's clipboard status. Restore any input-source, input-menu, dictation, shortcut and VoiceOver settings you changed.
