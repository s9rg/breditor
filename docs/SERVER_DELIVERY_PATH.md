# Complete ordered native delivery path

This distinct native contract verifies the actual restore origin A, every
independently selected complete predecessor B/C1/... and the complete current
server D. It does not reinterpret the single-prior continuation contract or
change original recovery, transport, storage or activation defaults.

PreparedLogGenerationRecoveryHost::verify_delivery_path consumes complete native
joined backup values, a separately selected ordered identity vector and the
same actual host/owner's genuine current protected-stream proof. It authenticates
before inspecting the path, requires 1 through 4,096 predecessors and at most
2 GiB of their complete encoded bytes, and retains every literal selection.
Duplicate/no-op cuts are allowed; no history is trimmed to fit a budget.

Inside one actual room-then-raster transaction it checks native custody and the
exact current inventory/backup, then proves A <= B, B <= C1, every subsequent
adjacent link, and the final link to D. Complete native files and physical
manifests, original bytes and every retained ancestor raster are checked. A
later server containing two snapshots does not by itself establish their order.
In particular, native-identical raster forks can both be present in D while C2
still lacks a raster from C1. Author counters, visible content, JSON labels and
hash-chain order alone cannot prove that missing inclusion.

The resulting VerifiedServerLogGenerationDeliveryPath has no public constructor,
Default or deserialization path. Its identity family is
breditor/server-log-generation-delivery-path version 1, with ordered ancestors
and the unchanged original/current/participants identity. The proof retains
complete predecessor backup values and a weak-host protected-current proof, not
a native room/lease or a plaintext bearer token. check_live reauthenticates and
rechecks exact current state and all links. A byte-identical cold replacement
host needs a fresh runtime proof. Native, physical, ACL, registration and even
raster-only changes stale the old exact proof.

No document, comment, file, packet, receipt, role, provider mapping or serving
state is mutated. This proves native data integrity only, not provider closure,
client reconciliation, an outgoing ACK, writer permission or room activation.
The 4,096/2 GiB limits match factual-journal ceilings; full-file retention and
current captures still require size/long-session qualification.

## Functional evidence

Tests cover all forty original grammar/wire and independent document/review
history combinations, multiple physical cuts, a repeated cut, actual old offline
delivery, cold ownership with fresh proof renewal and future native Undo/Redo.
Refusals cover wrong authentication/hosts/pins, empty/mismatched/reversed paths,
stale current rasters and a real counterexample where each native-identical
raster fork independently passes single-prior verification against D, but the
ordered path correctly refuses. Budget boundaries and opaque compile-fail
boundaries are tested separately.

The activated native service fixture invokes this public API over all its real
observed snapshots on every capture. Source, installed-package and executed
bundle workflows require the full ordered native path as well as their original
B and explicit intermediate predecessor checks. Public fixture JSON is evidence
only; it cannot recreate the native runtime proof.

## Required before cold editing resume

still required to expose this authorization across a process/network boundary.
Saved path JSON, fixture booleans, old single-prior controls or journal reopen
must not substitute for that capability. The coupled delivery/journal prototype
still needs fresh resume reapproval, full current client/provider reconciliation,
unbound source adoption, metadata transport custody and joint room activation.
