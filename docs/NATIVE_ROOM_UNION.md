# Native room union preparation

Breditor can prepare one recovery result for a complete selected room whose participants need different proofs. An independent-delivery participant can merge two compatible offline branches while every other participant still passes exact native continuation and its existing family-specific packet, journal and upload checks. Both complete room inputs remain in the saved preparation.

This is an SDK-private preparation contract. It saves immutable data without retiring source actors, opening participant targets, acquiring replacement author leases or activating a server. The existing room-preparation and retirement protocols keep their original meanings and strict defaults.

## Per participant proofs

Every ordered member of the selected operational root must appear exactly once. A target declares either continuation or independent-delivery-union. There is no skip mode, implicit fallback, arbitrary adapter or permission recovered from an archive. At least one member must use union mode; an entirely continuing room uses the existing preparation protocol.

A continuation member passes the existing exact native proof for that member, selected-upload continuation at the tighter applicable limits, and the unchanged concrete reconstruction recipe. The per-member verifier does not certify any omitted member. Existing complete-room verifier entry points still compare the entire cohort.

A union member must use the independent-delivery source and output families. Each complete room input independently reconstructs its ordinary participant backup from the literal catalog source, original recovery input, parent records, actual operation-journal cuts, LIVE native recovery, retained packet stores, local versions and required raster bytes. Only those two exact reconstructed backups may enter the participant union. Fresh original comment-role windows are supplied separately for every union member.

The participant union preserves the current author's native Undo and Redo and compatible incoming document/comment contributions, merges retained suggestions, revisions, versions and relay registers under their existing conflict laws, and retains the two complete native-attached upload queues with an explicit selected result. Missing bytes remain pending; conflicting immutable identities or unknown own-author suffixes refuse.

## Complete room conservation

The before input is captured from the genuinely held selected owner. The retained input must bind the same complete ordered operational root and asset approval. Target namespaces, participant-union journals and the room journal are distinct from one another and every known source namespace.

Both full selected-room files are retained, including their selected upload queues. These queues are not interchangeable with the queues attached to native participant backups. Later execution must reconcile selected-before with selected-incoming and then reconcile that result with the prepared native output. This preparation does not perform those later mutable asset decisions.

All seven concrete source families remain represented in the output catalog; local-operation-snapshot still reconstructs through the existing flat-local output contract. Union mutation is currently specific to independent-delivery. Other divergent families refuse rather than losing one side.

## Cold semantic admission

The new archive contains the complete before and retained room files, every ordinary participant output and each union member's complete participant-union archive. Its reader re-admits the ordinary output catalog, obtains actual ABI descriptors through fresh readonly native replay, and reproduces every declared recipe.

For a union member, cold admission replays the nested union under fresh original-role windows, then independently reconstructs both branch inputs from their complete room cuts. Each branch must match its nested original selection, exact bytes and complete digest. A valid output built from unrelated inputs is rejected even if the outer manifest has been recomputed correctly.

Historical raster resolution stays member-scoped. A nested branch resolves from its own preserved ordinary backup, not a sibling participant or the union's selected alias. Readonly native readers and cancellation remain scoped and disposed. Archive accessors return immutable data tuples rather than exposing mutable internal slots.

## Identity and bounds

This new format uses total bytes plus manifestSha256 as its explicit outer selection. It does not claim that the manifest hash is a whole-file hash. Ordinary room and participant components retain complete SHA-256 verification. A potentially larger nested participant union is identified by its own manifest identity and receives full semantic admission through its existing reader, including every component digest.

The aggregate archive is bounded at 16 GiB, the canonical header at 16 MiB and the cohort at 1024 participants. Ordinary output aggregation and individual native digest bounds remain unchanged, including the existing 1 GiB digest ceiling and 1 MiB read chunks. These are validation ceilings, not measured maximum-size or latency guarantees.

## Immutable persistence

Inspection holds the genuine cohort and writes nothing. Preparation freshly rebuilds the chosen result, checks all target namespaces are absent, rechecks the actual source cut and creates one absent-only immutable room journal. It does not create the nested participant-union journal or any replacement participant namespace. The actual source cut is checked again after persistence and at the end of the held cohort scope.

A committed journal survives a lost completion; existing-only reopening semantically verifies it without silently creating a missing database. Storage and lock contexts are pinned before host callbacks. An aborted upgrade cannot publish an empty placeholder. Reads count records before loading the large blob, and uncertain pending opens retain their cleanup until the real request ends.

## Remaining architectural work

The [execution components](NATIVE_ROOM_UNION_EXECUTION.md) now retain both full queue decision edges and support genuine actor-preserving retirement and ordinary target restoration. The distinct [recovery runs](NATIVE_ROOM_UNION_RUN.md) now carry that provenance through warm/cold target recovery, actual author transfer and pinned selected-room reopen; an old exact-continuation archive cannot stand in for the mixed proof. Compatible union reconstruction is also required for the other source families and for incomparable retained-generation branches.

Original-role network fetch, independent comment and server-log generations, complete provider/client closure, authenticated server decision ordering, retained version/asset policy and whole-room serving activation remain release work. Existing finite history and journal budgets still need a lifecycle that preserves outstanding offline edits and future Undo. All V1 gates remain open. Cosmetic and browser-specific work does not close these architectural obligations.

The reproducible checks are scripts/check-native-room-union-sdk.mjs and scripts/check-native-room-union-installed.mjs. They use real pinned Rust/Wasm and seven-family native fixture inputs with controlled IndexedDB, locks and raster presentation. Installed and production-bundle runs use actual offline packages without workspace links. Their result files distinguish reused verified native fixture data from a fresh Rust producer run.
