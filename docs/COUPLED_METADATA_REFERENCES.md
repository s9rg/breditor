# Coupled metadata reference capture

The private metadata owner offers a separately named captureReferences operation.
It nests the literal existing metadata-room bundle and a new hashed reference
file. Existing formats, defaults, public exports and original protocols do not
implicitly accept this additional envelope. Reference Ready means complete
dependencies at these points; it does not mean image bytes are available.

The parent's actual quiescence covers the entire operation. Source/context work
drains before it captures the seven-family base room. The metadata owner then
reads the real committed journal and pins that exact complete stored snapshot,
including original before-state, packets, receipts and current source cuts.

Before any new metadata write, constructor-selected factories replay readonly
aliases at the original and stored points. Native continuation proves their
order; original packet and receipt admission runs at each point. The actual live
core must extend the stored alias, and both document/comment read stamps pin that
core through the remaining operation. A stored cut is never read against a newer
live core merely because the writer ID or final text matches.

The next metadata write saves the actual paired sources and uses the original
full-record CAS, additionally requiring that its freshly read old bytes equal the
observed stored snapshot. A changed stored head refuses without overwrite. The
new current point must match the actual live native journals and the parent
bundle's complete native/relay rows. A changed document or comment stamp refuses.

One reference file pins the literal multipart parent identity, complete original
base history, the earlier full stored metadata state and ordered before/stored/
current lane reads with exact state length/digest identities. The union includes
native histories, retained/cached versions and all original proposal/revision
packets, including intermediate and deleted image generations. Unreconciled base
participants, missing native source clocks or uncached version packets produce
global Pending with no partial Ready reference set. Actual original authenticated
cache downloads can produce a new Ready decision without changing old records.

Capture registers its actual promise and excludes reentry before host permission
callbacks. The same lifetime gate also protects the original metadata capture.
New reference work owns its factory/cancellation scopes and claimed readonly
aliases. Close cancels finite reads and uses existing late-raw-owner cleanup;
actual capture/hash promises remain tracked until they settle. A cancelled export
keeps any newer committed metadata and cannot turn it into a successful export.

Native functional qualification covers genuine seven-owner preparation, all
three local bindings, proposal/revision-only images, Pending and real catalog
downloads, actual remote updates newer than stored metadata, nested capture
refusal, delayed real hashing during close and future document/comment Undo/Redo.
Independent package verification repeats it beside the existing full cold/restore
workflow and strict types. Node IDB/locks are controlled; native histories and
authenticated original relay requests are real.

Still required are fresh native re-admission of portable reference envelopes
when consuming them for recovery, actual provider/client/packet/upload byte
reconciliation under current authenticated requirements, and joint activation.
No parsed reference file, digest or dependency decision creates an actor or
provider capability. All thirteen full V1/parity gates remain open. Rust/Wasm,
package versions, protocol meanings and default data formats are unchanged.
