# Native-held suggestion delivery

Status: [source and independently installed qualification passed](qualification/2026-10-29-native-suggestion-delivery.json): 871 direct checks, 299 installed checks and strict source/installed contracts. All thirteen V1 gates remain open.

This private execution path borrows the original suggestion queue, its exact
constructor-owned source, and a genuine native recovery context. It delivers
the retained immutable packets and queued decisions through the existing
authenticated server protocol. Ordinary editor and queue mutations stay
excluded. Public exports, nominal public constructors, saved identities,
protocol meanings and default behavior remain unchanged.

The actual author or permanent-observer constructor registers its transport
against that same execution context. Copied facades, matching DTOs, another
context for the same editor, and replacement storage callbacks cannot select
it. Execution options accept reporting callbacks only. The original queue's
recovery gate also excludes its ordinary attached sync and revision adapters.

Each staging operation and actual asynchronous write owns explicit per-call
work admission. Native history adoption uses the original verified effect and
guarded native ingress; accepted commands are never executed again. A separate
queue saves its original native source before saving the dependent receipt.
Compound sources use their existing atomic record driver.

Server finalization and local persistence are separate facts. A failed receipt
write retains its original winning decision, packet and pending record for
explicit local retry. Actual committed bytes become durable facts before a
post-commit authority check. An interrupted response is resolved from the
original server feed in a fresh context, without submitting another decision.
Both owned and unowned history semantics survive a cold reopen, including
future independent document and comment Undo/Redo.

Permanent observers retain a zero authored prefix, resume only their observer
lease, and never submit document authoring or Accept. An existing queued
Accept stays pending and reports permission denial; Reject uses the original
server decision order. Document read-only policy does not remove independent
comment permissions or flatten review generations.

Two observer defects were reproduced while implementing this path. A pending
ordinary observer connection was missing from native recovery work custody.
Also, checking the native recovery grant inside synchronous document
publication disconnected the observer's own import. Observer work is now
tracked; passive held-publication checks run after publication finishes.
Compound observer startup additionally distinguishes explicit Connect intent
from intermediate transport status, while Disconnect and failed operations
still invalidate that intent.

Closing retires the private sync, drains its actual SDK calls and pending
store writes, and releases only its queue loan. It does not retry a failed
write, discard the original queue, release native recovery, or activate a room.
Cancelled token acquisition cannot open an old socket after a late result.

Functional qualification uses real Rust servers, the pinned normal Wasm,
controlled IndexedDB/Web Locks and controlled transport interruptions. Tests
cover all six bound source families, three selection policies, explicit and
typing grouping, owned and unowned accepting history, permanent observers,
receipt aborts, post-commit authority loss, lost Accept replies, cancellation
and authenticated lazy packet caching. The same files run from fresh package
archives with locked dependencies and no workspace links. Complete-room
coverage also exercises prepared metadata while retaining pending revisions.

The [native revision path](NATIVE_REVISION_DELIVERY.md) now shares this exact
queue loan and drains revision children before parent close. All thirteen V1
gates remain open. Explicit metadata bindings for the three local source lanes,
complete provider/client/historical-copy and asset reconciliation, and
authenticated joint activation remain required. These checks do not qualify
physical browser durability, accessibility, or the historical WebKit fault.
