# Cold room execution

The SDK-private cold executor continues an existing interrupted room replacement without an original editor, selected-asset owner, or stopped actor cohort. It acquires fresh local document and comment actors, admits the complete original against the immutable replacement, and reuses the existing seven-family target recovery path. Native document and comment history, retained packets, both upload inventories, and selected upload queues remain part of admission.

This is local ownership recovery, not permission to serve a room remotely. The host must independently select the current original, run identity, target policies, read factories, and temporary source-custody namespace. The existing warm executor retains its original meaning and defaults.

## Source admission

The immutable execution contains the before cut and retained cut from preparation. A reopened original can be older than the captured LIVE cut: for example, an editor captured offline work after a source save failed. Requiring equality with the before file, or requiring the saved original to descend from its LIVE state, would reject that valid recovery.

The cold executor instead proves that the actual reopened original fits within the already-admitted retained output. It replays document and comment history through the selected native read factories and requires real native ancestry into the retained output, including immutable local versions and relay progress. Matching document text is insufficient.

Packet content and save acknowledgement are separate. Each actual original committed, pending, and LIVE packet record must match a captured variant. The queue and revision outbox normalize their save slots independently; every packet, publication, retry, decision, conflict, and receipt field remains significant. Retained generation and delivery packets must either match a captured variant or conserve every whole existing row through the existing retained-packet continuation check. Previously captured native or packet states are observations, not new permissions.

Both complete native-source upload inventories and selected upload inventories must continue into the retained output. A new receipt, retry, raster, or native edit absent from that output requires a new reconciliation. The executor preserves the actual source and refuses the stale plan; it does not select a winner by timestamps or roll the source back.

## Inspection and deliberate repair

preview() uses complete-existing admission. It does not acknowledge pending native journals, repair incomplete original parents, or create a replacement destination. A denied run decision does not append progress or close originals.

repairOriginal(approve) is a separate fresh decision scoped to repairing the selected existing original. It may finish its genuine pending journals through the ordinary recovery implementation. It does not start a target, grant remote serving, or bypass the later source-containment check. The caller must obtain a new preview and approve that exact source selection and current journal head before execution.

Unknown work uncovered by repair remains in the original even when the retained replacement cannot contain it. Provider and native-author union is a distinct reconciliation capability, not an implicit fallback in this executor.

## Fresh custody and execution

The complete source and target namespace sets, same-author identities, family-specific policies, and immutable execution recipes are admitted before any fresh actor request. The journal, preparation, native targets, both catalogs, both roots, adoption and approval stores, selected upload destinations, and temporary source-custody namespace must be disjoint where their roles require separate storage.

Root, source, and read authority checks must synchronously return undefined. A Promise, thenable, boolean, or other returned value is not a successful grant, even when an intermediate wrapper ignores its return. Both cold entry points retain the shared checked callback rather than the raw function; rejected asynchronous results are drained.

The attempt exists synchronously before asynchronous opening begins. It retains actual journal, actor acquisition, original parent, unreturned opening, selected-store, and target resources through rejection and cleanup retry. No writer is restored from a serialized stopped flag or saved completion event.

Original selected upload stores remain under actual namespace and whole-store custody across target construction and the final promotion barrier. Their lifetime is bound to the held fresh actors, current source/read permissions, and original storage context. It does not reuse a root-busy callback after the original root closes.

After a fresh affirmative decision, the executor rereads and rechecks the exact source and head. It closes all original native borrowers before replacement constructors borrow the same actors. It appends the existing advisory resume stage and recovers existing started destinations through their original protocols. It never fabricates a retired event for newly acquired actors or treats a historical retired event as current authority.

## Promotion and failure recovery

Target promotion still requires its separate complete current native, packet, selected-asset, actor, and parent barrier and a fresh promotion decision. The actual successor is staged in a reachable recipient before any ownership flags move. Original upload custody lasts through this barrier.

If old-source cleanup fails after promotion, the successor stays in that recipient. complete() retries only old cleanup, without repeating promotion and without requiring the ended finite read job to become authorized again. takeOwner() refuses until cleanup completes and reserves its one-shot pointer take before synchronous abort observers run.

close() abandons the attempt without deleting or overwriting source, intent, target, or journal data. It waits for actual children and late/failed openings before releasing actors. A rejected close retains the same resources for retry.

## Qualification and remaining scope

The functional workload uses actual Rust native histories with controlled IndexedDB, locks, and local native fixture servers. It exercises interrupted native construction and selected-asset adoption, fresh acquisition after all original handles close, captured-but-unsaved history, explicit pending-journal repair, stale-plan refusal, and post-promotion cleanup. Pure packet tests cover the separate save-slot content rule; strict type fixtures keep choices distinct from native ownership and serving authority.

Controlled storage and cleanly stopped handles do not certify a physical operating-system crash. Existing-complete replacements with additional later work require their own qualification. Full provider/client and author-union reconciliation, authenticated whole-room activation and cross-device fencing, independent comment/server-log generations, sustainable retention, and all other open V1 gates remain required. This checkpoint does not declare release readiness or full feature parity.
