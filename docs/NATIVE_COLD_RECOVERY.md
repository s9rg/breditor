# Native service and seven-client cold recovery

This qualification joins the durable Native service restart with the actual
seven-family SDK recovery path. Source and independently installed consumers run
the same five required cases: all four independent document/comment history
policy pairs, plus a separate two-restart authentication regression. The Native
fixture uses rich language 3, standard schema and atomic writer transport.
Existing lower-level profile and wire-mode qualifications remain separate.

## Ordered recovery

Each history case starts genuine registered Native writers and comment actors,
creates real metadata lanes and uploads, and completes the original delivery
protocols. Original catalog packets remain uncached. The current Native/source
reference union and provider read are checked without fetching historical packet
or raster bodies; old Pending/cache meanings remain literal.

Before restart, each client creates a real offline text edit and comment. The
complete current client archive is written, synced and read back. Live delivery
contexts disconnect. Rust captures a durable Native restart checkpoint under
fresh owner authentication and all fourteen protected registrations. Every
control, inspection and HTTP/WebSocket task drains before old Native custody
is dropped. Recovery reopens the same operational directory, authenticates
again and commits the exact next epoch. The fixture records the actual prior
and current choices and returns to the same socket bindings.

All seven SDK clients close and reopen as new Native owners under fresh read
permission. Their exact independently selected policies, checkpoints and real
upload ACKs must survive. Expired whole-room writer grants stay unused. A new
current read must still identify all fourteen offline heads as Pending; a saved
checked report cannot acknowledge them.

Two real protocol passes then deliver the outstanding work. A fresh current read
must be checked, with complete provider assets and fourteen whole upload roles.
Original metadata bytes, cache states and old receipts remain preserved. Every
client subsequently performs document and comment Undo/Redo, restoring exact
document content, complete comment views and history depths. Materialized raster
bytes are also read and verified offline.

The authentication case separately performs two Native restarts. New account
tokens work and prior account tokens fail. Registered document/comment credentials
remain the same, avoiding a cloned author or lost offline identity. Actual room
identity and original raster bytes remain unchanged.

## Reproducible checks

`build-native-cold-restart.mjs` builds only the dedicated restart and complete
control fixtures in a separate target with a monitored 3 GiB allocation limit.
Previously qualified executables and normal Wasm are protected. Native tools,
source and runtime hashes are checked before and after the workflows.

`check-native-cold-restart-source.mjs` and
`check-native-cold-restart-installed.mjs` require all five real cases and strict
public types. The independent consumer installs exact offline archives, uses no
workspace SDK links, copies the checked Native executables and permits only
reversible fixture/module-location rewrites. Both release profiles require the
build, source and installed checks. Evidence laws refuse missing/repeated policy
pairs, unchanged epochs, missing offline heads or ACKs, populated caches, failed
comment restoration and accepted expired tokens.

The [qualification record](qualification/2026-11-01-native-cold-recovery.json)
retains exact executed source, package archives,
Native binaries, public snapshots, client/review/metadata/raster archives, actual
observations and logs in a read-back-verified proof. No shortened acceptance mode
or implementation substitution is provided.

## Boundaries

These are controlled service restarts within one Rust process and genuinely new
client owners within each Node process. Local IndexedDB, locks and raster
presentation are controlled fixtures. The result does not certify an OS process
crash, real browser storage, physical power loss, cross-device fencing or public
hosting. Fresh host account configuration is separate from saved document data.

Rust production APIs, original wire protocols/defaults, normal Wasm and package
versions are unchanged. The new Rust modules are opt-in functional examples.
Authenticated production whole-room activation, complete candidate profiles,
remaining feature parity and all thirteen V1 gates remain open.
