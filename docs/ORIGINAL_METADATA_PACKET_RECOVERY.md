
# Original metadata packets and recovery bytes

This is an opt-in candidate recovery capture. The operational metadata owner
remains internal. Additional immutable DATA types are exported from the package
root. Original publication, acknowledgement, receipt containment, V1/V2 raster
formats and existing recovery captures retain their meanings.

## Capture

The genuine SelectedLocalMetadataDelivery owner exposes:

- capturePacketRetention({host, inventory}) retains additional metadata strings
  and their Native dependency read alongside the original reference bundle.
- capturePacketRecovery({host, inventory, server, transport, limits?}) also retains
  the independently selected Native server and participant-inventory files and
  attempts the complete additional raster union.

The controller is the actual delivery-continuation host. Server and inventory
readers and the asset transport must be genuine instances. Inputs are detached
inside the original registered finite task, before account callbacks or IO. The
same seven held Native sources, original source factories, current server cut,
all fourteen upload archive roles and metadata journal remain checked throughout.
Public method shadows and structurally copied controllers do not supply a port.

capturePacketRecovery returns kind retained or pending with a bundle in both
cases. Its format is breditor/selected-local-metadata-packet-recovery-bundle,
version 1, with scope
client-metadata-first-server-packets-and-selected-recovery-files. Selected server
and inventory bytes are retained before additional asset resolution. Missing
Native packet sources, missing opaque mappings or missing raster bytes stay
explicitly Pending. Pending never silently becomes an empty complete asset list.
A failed operation does not erase the original journals or pending work.

Retained describes bytes at this cut. Original containment and reconciliation
are nested under their original names; their Pending results keep their meaning.
This result does not grant a serving role, acknowledge an upload, settle an
outbox, accept a proposal, import a frame into an offline writer, or activate a
room. Ordinary owner capture may persist its usual capture checkpoint.

## Original packet identity and literal strings

The archive includes each first accepted server version, suggestion and committed
revision body from the complete original catalogs. It separately indexes every
original local metadata occurrence from committed, pending, attempted, retained,
live and original/input backup points, including the three additional local
before/current metadata lanes. Revision occurrences retain their exact predecessor
strings. Original local version-history files remain in the unchanged parent
Native/reference archives.

Native content IDs match original acknowledgements. They are not literal byte
hashes. A Native-valid JSON variant can have the same ID and a different original
string; the archive retains both. Server fingerprints select the first accepted
body and cannot be satisfied by substituting a differently encoded local retry.

Bodies use JSON-string-v1 storage. The inner packet is never parsed and
reformatted. This also preserves original local UTF-16 strings containing an
unpaired surrogate, even when Native UTF-8 conversion normalizes that string.
Storage bytes and digest therefore remain separate from the original Native text
fingerprint. Each body is independently hashed, and every local/server occurrence
points to its storage key. Deduplication uses encoded bytes rather than Native ID.

The independently framed packet manifest is
breditor/original-metadata-packet-retention, version 1. Payload chunks are at most
64 MiB. Original packet admission remains limited to 4 MiB of Native UTF-8 text;
there are at most 100,000 retained bodies and 100,000 local occurrences, with a
256 MiB manifest bound. Native hashing reads at most 1 MiB per update. Readers
check canonical framing, all declared chunk coverage, exact strings and digests,
complete declared catalog consistency and predecessor identities. Disposal drops
reader state and refuses late asynchronous body success.

## Native dependencies and images

Actual held Rust cores read dependencies from each exact packet, including
intermediate/deleted proposal images and both sides of a revision. A missing
source clock may be resolved by another actual held source. Arbitrary Native
errors are not converted into Pending. No accepted frame is imported into an
exclusive offline writer just to make its dependency read succeed.

The additional raster format is breditor/original-metadata-packet-assets,
version 1. Its scope is complete-base-packet-and-whole-upload-raster-union:
Native base/reference-cut dependencies, all newly resolved packet dependencies
and every original/selected upload ID. Local bytes and authenticated downloads
are decoded and checked against their content IDs, sizes and dimensions. Locally
durable bytes may remain retained while the original provider still reports a
missing upload; no acknowledgement or storage reference is invented.

Raster payloads use bounded 64 MiB chunks with an independently hashed manifest.
The manifest pins the exact original reference and packet manifests, complete
requirements, original provider read, local raster metadata and complete payload
coverage. Its encoded manifest bound is 16 MiB. Existing raster limits and the
1 GiB aggregate encoder bound apply; no partial prefix is returned as retained.
The provider requirement check repeats before return. Cache mutation and implicit
uploads are excluded.

## Reading saved data

The internal MetadataPacketArchive and MetadataPacketAssetArchive classes read
portable immutable bytes. Recorded catalogs do not acquire the live catalog
collector's private provenance. A consistent rehashed DATA envelope cannot prove
that a recorded server catalog describes a real restored server. Native packet
identity and source checks require real Native readers; server completeness and
current rights require actual server reconstruction and fresh authentication.

The server file contains the complete independently selected physical Native and
raster backup, including physical records outside the committed metadata catalog.
The extra packet manifest indexes original committed catalog bodies and local
metadata records. It does not relabel inert revision preparations as publications.
Those physical records remain in the selected server backup. A future complete
server reconstruction must replay them and recompute its complete physical Native
packet/reference inventory rather than trusting this manifest's declared catalog.

A source-owned portable inspector for this additional bundle, the server-side
Native dependency path when all selected clients lack a packet's historical
source, actual successor reconstruction, independent comment/server-log
generations and authenticated whole-room activation remain required. They are
not implied by raw archive readback or the current component qualification.
All thirteen V1/parity gates remain open.

## Reproduction

Build the unchanged normal packages and the separately pinned Native examples,
then run:

    node --test --test-concurrency=1 scripts/metadata-packet-archive-native.test.mjs scripts/local-metadata-packet-recovery-native.test.mjs
    node scripts/check-local-metadata-packet-recovery-installed.mjs

The full seven-family workflow repeats the original receipt-containment checks,
including a valid-frame omitted receipt while original outboxes remain checked.
It then publishes a fourth real PNG used only in an intermediate command of a
new server-side proposal. The image is absent from every selected upload archive,
all local packet rows and the current editor document. Capture retains 17 first
server bodies, 82 local occurrences and all four images. A content-addressed
multi-file disk roundtrip preserves the exact packet/image/server/inventory bytes;
real held Native cores reread packet dependencies. The existing subsequent
Native document and comment Undo/Redo checks run for all seven families.

Focused tests additionally cover original Native-valid local string variants,
unpaired-surrogate preservation, private ports, cancellation, stale metadata,
reader disposal, corruption, rehashed payload omission and missing authenticated
downloads. The independently installed consumer repeats the same tests and strict
public types from npm archives without workspace links. Exact results, frozen
sources and artifact hashes belong in the checkpoint qualification record.
