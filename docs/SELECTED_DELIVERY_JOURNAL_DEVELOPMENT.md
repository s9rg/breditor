## Actual ownership and sequencing

delivery gate, a genuine initial current operator checker, native server archive
and participant-inventory reader. Cheap private gate/scope identity checks precede
application callbacks. Its opening options and native reader intrinsics are
captured before callbacks. Initialization consumes the gate once, registers the
new cleanup owner before its first await, quiesces real contexts, rechecks the
complete before-cut and absent-only commits/read-admits the initial factual row.
It tracks initialization itself so concurrent close cannot release resources
while the actual opening is unfinished.

The preparation gate has one exclusive private handoff. Existing unclaimed
callers retain their original behavior; after handoff, legacy construction
refuses. Both document and review adapters for one genuine source share the
same actual context. createDelivery reserves construction before callbacks and
requires a successful factual checkpoint before another source step. Every
admitted native callback remains restricted by the actual scope, preparation
owner, journal lifetime and fresh application policy.

adapters before capturing progress, including genuinely committed saves whose

During recording, new adapter construction and reentrant journal work refuse.

## Failure and resource contracts

Any admitted record failure automatically stops the real preparation/delivery
gate before rejecting. A write that committed before a later policy refusal is
retained. readFacts can inspect such immutable data while the same root/resources
remain owned, but never reopens the gate, creates an ACK, retries a native save
or permits more delivery. A busy reentrant call refuses without disrupting the
already-admitted job. There is deliberately no resume or activation method.

close marks the owner closing, starts actual adapter drain, waits for real
initialization/record/read work, then closes the journal's actual pending
IndexedDB requests, namespace custody and WebLock. Cleanup uncertainty remains
owned and retryable; it cannot be declared finished from a canceled public
promise. Parent visitor cleanup invokes a captured private closure, not a public
prototype override. Complete originals and committed facts are never removed.

The factual storage contract keeps its five stores, atomic absent-only start,
store-branded snapshot witness and exact comparison of every old complete byte
inside the append transaction. Each fresh load re-admits complete nested client,
server and inventory files. Its 4,096-entry/2 GiB bounds refuse exhaustion rather
than trimming native history. Full-byte materialization still needs size tests.
