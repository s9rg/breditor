# Durable native execution

The private execution coordinator imports original server-accepted document and
review operations into a genuine selected room. It saves complete recovery data
before admission and retires every selected native client after an uncertain
outcome. It does not adopt unbound comments, acknowledge source durability or
activate a room.

## Approval and authentication

A start preview contains the independently selected immutable input and the
actual complete current file. Execution requires that exact choice and a fresh
affirmative decision while native edits, publication and selected asset writes
remain excluded. A stale choice or denied decision cannot create progress or
change a client.

Every original accepted request is reissued through an independently configured,
brand-checked host before importing. Saved response data is not authentication.
Historical policies, frames, receipts and bindings must match; only the current
reader role may change. That reader role never changes recipient permissions.
Only actually bound review lanes receive accepted review batches. Intentionally
unbound lanes remain pending.

## Complete progress before and after admission

The absent-only prepared transaction stores the input, complete current file and
canonical client cohort together. It commits before the first native admission.
The journal uses four closed stores: intent, events, cuts and evidence. Occupied
start namespaces refuse without replacement.

Each client event saves another complete source, native, packet, journal and
whole-upload cut. Events form a hash chain and append through an actual
store-owned snapshot witness and a compare-and-add transaction. Callers cannot
supply copied metadata as that witness. An existing journal is read without
creating a missing placeholder; all input, event, cut and evidence hashes are
checked again.

A read event retains a fresh reconciliation diagnostic. It is not a completion
flag, backend acknowledgement or serving decision. The final native, source and
upload cut must still match after this event commits.

## Uncertain outcomes and resume

Once any native admission is attempted, an error retires every actual client
synchronously before the common exclusion is released. Durable source close
then finishes outside the visitor completion promise. The executor does not
silently discard memory when close fails.

A resume preview opens the real existing journal and proves every retained cut,
including intermediate cuts, precedes one actual current native, source and
upload cut. Equal document trees or clocks cannot replace native ancestry.
The selected current cut may include newer offline work.

Each resume requires a newly selected exact journal head, current cut and
affirmative decision. It commits a complete resume before-state before further
admission. All original accepted inputs are replayed idempotently for every
client. A saved client cursor or read stage never skips an import.

Closing an input handle releases only its own resources. Existing retained input
can be reopened under a fresh independent read grant without recomputing it from
a newer selected room.

## Limits and remaining work

The journal is bounded to 4096 events and 1 GiB across complete input, cuts,
evidence and metadata. A diagnostic is bounded to 16 MiB. Exhaustion refuses
without truncation, overwrite, implicit compaction or protocol changes. Complete
cuts make the current implementation storage- and replay-intensive; sustainable
history is still required for long-running shared documents.

Cold resume currently requires genuinely reopened sources whose native history
extends every retained cut. If disk storage is older than retained live work,
resume refuses and retains the data. Explicit reconstruction into absent source
namespaces is still required; refusal is not recovery of that work. The
[native reconstruction paths](NATIVE_RECONSTRUCTION.md) build original and
independent-local participants from retained LIVE work and restore them into
absent component databases, including all four independent native history pairs.
Full seven-family room reconstruction and native union remain open.

Functional tests use actual native clients and source close/reopen, with controlled
browser storage and namespace locks. They do not qualify physical power loss.
Explicit local-comment adoption, authenticated whole-room activation with old
writer fencing, sustainable history, extension parity and all thirteen V1 gates
remain open.
