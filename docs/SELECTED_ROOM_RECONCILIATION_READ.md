# Selected room reconciliation reads

The SDK-private selected owner can inspect every actual retained native client
against the accepted authors in its independently selected room inventory. The
same operation holds complete source and packet records, both whole-upload
generations, and a fresh authenticated provider read. It reports missing history
without importing peer frames, relabeling local comments, acknowledging work or
activating a room.

## One actual resource cut

`RetainedSelectedAssetOwner.readReconciliation(host, input)` uses the owner's
existing retained root and selected stores. The root supplies its private native
clients and the genuine complete record reservation directly to the reader.
Caller data cannot supply another core, inventory or record scope. Temporary
native readers belong to that same reservation; the operation does not construct
replacement editors or borrow a second source cut.

The inventory's original file, identity and metadata are read through captured
class methods and checked against the catalog's independently selected current
inventory. Its cached accepted clocks become current authenticated evidence only
through the genuine separately configured operator host. The host must still
match the catalog's ancestor, server and participant selections.

## Accepted author coverage

Each selected native client is checked against every registered document writer
and every server document author, including genesis and suggestion effects. A
local head below the accepted counter is pending. Otherwise, the native prefix
at that exact accepted counter must match the inventory digest. Both existing
transport digest families retain their meanings. A conflicting prefix refuses
the whole read even when another author is behind; an earlier pending result
does not stop the remaining comparisons.

Every explicitly bound review lane is also checked against every accepted
review actor and its principal. An unbound local lane stays unbound even if its
actor appears in the inventory. Absent and unbound lanes contribute no global
review proof. Original and independent document/comment history policies remain
separate, and unsupported native author-prefix capabilities refuse this new
read rather than substituting JavaScript history reconstruction.

`documentAuthors` and `reviewAuthors` declare accepted authors once. Each
participant's `documentHeads` vector aligns with `documentAuthors`; a bound review
lane's `heads` vector aligns with `reviewAuthors`. Comparing canonical counters
identifies pending entries. Every non-behind entry has passed the native digest
comparison. Empty review vectors do not assert coverage. This avoids repeating
author declarations across a large room without truncating any comparison.

The existing own-author inventory scan additionally retains room, schema,
principal, writer, observer and binding validation. LIVE suggestion, revision and
version declarations are matched to that native room. Complete source readers
remain responsible for admitting their retained original, committed, attempted
and pending states under those immutable store identities. Local version packets
are not relabeled as server version catalogs.

## Provider evidence and final publication

The existing provider composition checks complete historical references and
every origin and selected upload store. Missing bytes remain pending. An
incomplete historical cohort authenticates control but never sends a smaller
asset request as though it were complete room availability. All selected queues,
source records and retained stage/intent files are re-admitted after I/O.

Real temporary read and selected-store cleanup finishes before the new reader's
last fence. An independent cancellation observer remains live across that
cleanup. Fresh read permission then precedes exact checks of the actual retained
native checkpoints, history policies, publication epochs and root lifetime.
Cancellation is checked again before publishing the result and advancing the
successful upload baseline. These checks do not reuse disposed readers. A late
native edit is preserved but invalidates the prepared report; a subsequent read
can inspect the new state normally.

Routine I/O liveness uses genuine facade epochs. Full native bytes are compared
at capture, lineage and final publication boundaries instead of being serialized
on every hashing chunk. Existing capture and provider-read defaults are unchanged.

## Result and remaining recovery work

The deeply frozen result is `checked` only when all required native coverage and
the provider read are complete; otherwise it is `pending`. A fork or changing
resource cut refuses. These are detached point-in-time diagnostics, not custody,
credentials, a durable acknowledgement, an editing grant or activation authority.
No public package-root export, Rust/Wasm contract, stored protocol or version is
changed by this private composition.

Actual repair still needs authenticated transfer of missing accepted operations
without incorporating another client's unacknowledged offline work. Unbound
local comments need an explicit adoption contract that retains their original
lane. Whole-room activation must then exclude old writes, recheck the final cut,
retain an authenticated durable decision and publish the serving epoch under
that exclusion. A successful read alone satisfies none of those mutation steps.
Sustainable Undo/offline retention and remaining extension parity also remain
part of the V1 goal.

## Reproducible functional checks

`scripts/check-selected-reconciliation-sdk.mjs` and
`scripts/check-selected-reconciliation-installed.mjs` combine all 1,958 prior
selected-owner test bodies with 27 additional bodies and 24 strict consumer
fixtures. The installed checker repeats those same laws from offline packages
and their actual production bundle with reversible fixture-location changes.
Fresh source-matched native inputs, exact normal Wasm bytes and unchanged source
are prerequisites. Passing this scoped workload is not full V1 qualification.

The new fixtures use actual native registrations and authenticated local native
controls. Positive setup explicitly exchanges histories before capture, never
inside the reader. Other cases retain genuinely missing peers or create genuine
document/comment author forks through native actions. Cleanup races hold real
lock-release acknowledgements; deliberately authored late edits remain intact.
Controlled storage and presentation fixtures do not certify physical durability
or browser behavior.
