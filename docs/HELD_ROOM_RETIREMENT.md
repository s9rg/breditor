# Retirement checks within one held source lifetime

The SDK-private `verifyHeldPreparedRoomRetirement` entry verifies an existing
complete preparation inside the genuine selected Native source scope. It does
not release that scope or acquire a second reservation. This is a prerequisite
for coordinating metadata activation and old-client retirement under the same
owner; the production joint activation attempt is still required.

The actual selected-owner registry supplies the original read factories and
sources. Copied scopes, proxy-shaped scopes and saved source reports are refused
before inspecting caller options. Bounded Native restore wrappers and explicit
cancellation belong to this finite inspection; the outer selected owner retains
its own source lifetime and cleanup responsibility.

Both this entry and standalone retirement use the same admission code. It checks
the actual complete before-cut, retained Native ancestry, complete selected
uploads, the stored preparation, every reconstructed participant recipe and a
fresh affirmative approval. It then asks the genuine outer retirement scope to
retain its final current witness. The outer owner checks that witness again and
retires the actual writers before releasing Native exclusion.

The returned inspection says `complete-original-cut-verified` and
`same-held-native-source-lifetime`. It does not claim `old-writers-closed` while
the outer callback is still running. Only completion of the outer retirement
operation proves that transition. The stopped actor cohort remains under the
existing actual reservation and one-shot take; no report or saved stage supplies
actor custody, credentials, queue acknowledgements or serving rights.

Cancellation of the outer current-cut capture still belongs to the outer source
lifetime. The new qualification covers an already-aborted inspection; late host
factory cancellation during that capture is not qualified by these cases.

The new source and independently installed cases cover both mixed document and
comment history policies, all seven genuine source clients, fourteen actual
actor locks, an await in the approval callback, refusal followed by an explicit
retry, an already-cancelled inspection and forged-scope admission. They compare
the complete original store bytes and keep the original source objects identical
through inspection. The existing four standalone retirement cases additionally
restore concrete target histories for every document/comment history policy pair.
Strict source and installed declaration checks keep the entry private and prevent
inspection data from being used as a source scope or activation result.

The qualification record retains the exact executed source, archives, package
byte comparisons, Native/Wasm identities, actual fixture data and read-back-verified
compressed proof. The first sandbox-only attempt could not open its private
loopback service; its original failure log is retained separately. The authorized
Native runs use the actual local executable with controlled IndexedDB and locks.
Rust implementation, normal Wasm, versions, original formats, defaults and public
root exports are unchanged.

This component does not implement the returned joint activation attempt,
uncertain-outcome custody transfer, normal router publication or general
cold-process deployment management. Those remain the next architectural work.
The historical archive-read/WebKit faults, full candidate profiles, physical
storage qualification, remaining catalog parity and all thirteen V1 gates remain
open. No push, tag, publication or deployment is part of this checkpoint.
