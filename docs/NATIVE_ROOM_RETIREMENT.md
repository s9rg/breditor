# Explicit native room retirement

The private `native_room_retirement/` SDK closes the actual old writers only after
re-admitting a complete durable preparation and obtaining fresh approval. It is a
local recovery boundary, not whole-room target execution or serving activation.
Existing DATA inspection and import/quarantine routes retain their old defaults.

## Inputs and decision

`retirePreparedRoom` requires the genuine selected owner, current native read
factories, the complete retained room file, the independently selected preparation
choice and a fresh affirmative decision callback. It reads an existing immutable
intent; it never creates a missing intent or trusts a phase marker as permission.

One held native/upload scope checks the actual complete source cohort and both
room cuts. Every saved output is independently admitted through its concrete
participant format and rebuilt using the original, generation, independent-local,
independent-delivery, restored-graph, snapshot-to-flat or flat recipe. Family,
selection, byte length, MIME and native digest must match exactly. An internally
valid older output is insufficient when newer retained LIVE work exists.

Retained asset bytes are resolved from one admitted member at a time. A matching
alias in another member cannot provide its bytes. These local bytes are not a
provider receipt, current remote credential or save acknowledgement. All packets,
literal inputs and both native history lanes retain their existing meanings.

The callback runs only after complete re-admission. While it waits, all actual
native members remain under common exclusion. Decline, cancellation, missing
intent, stale sources and admission failure do not retire the sources. A final
current cut, authority and cancellation check precedes retirement.

The common reservation holds the dependent metadata queues through the final
authority callback. A suggestion retry flag has its own state outside the
document and comment observations. The final capture retains genuine native and
packet witnesses from the same source readers. After the temporary readers close,
each independent source must equal its captured live value. This synchronous check
runs after the last authority callback and before the first core retires. A
mismatch leaves the changed intent and every old writer live. Inherited
origin-upload custody stays with the root.

## Retirement and cleanup are different states

The successful boundary synchronously retires every actual old core before common
exclusion is released. It starts the canonical selected owner/root cleanup, then
releases the visitor completion promise before awaiting that cleanup. Waiting for
Close inside its own visitor would wait on itself. No fake import is used to
trigger retirement and no replacement writer is created by this call.

Native retirement ends mutation authority for every attached queue, revision
outbox, version catalog and relay-progress record, independently of adapter
teardown order. Entry guards and final pre-staging guards check the actual native
owner, including when validation or asynchronous opening retires it. A genuine
revision-closing notification cannot add an intent to a still-open sibling queue.
New adapter factories refuse an already retired owner before creating storage.

Pure exports and completion of already captured persistence work remain available
until explicit disposal. This is not document read-only mode: an active read-only
document retains its existing metadata operations. Cleanup does not create a new
proposal, change a retry choice or accept a new relay cursor.

A closed native core can still owe a namespace lease release. The delivery owner
therefore tracks cleanup completion separately from native retirement. The graph
operation journal fences reads as soon as retirement starts but marks itself
closed only after its actual cleanup obligations succeed. A failed release can be
retried through the same actual close/discard handle; retry neither saves again
nor revives an editor. Every cleanup action is attempted even if another fails.

After successful cleanup the returned report says only `old-writers-closed` within
`local-native-and-selected-asset-custody-only`. It contains no native owner or
activation capability. Source databases and the immutable preparation remain
unchanged. On a cleanup error, the old writers remain retired and the caller must
finish cleanup through the same owner; rejection does not mean retirement rolled
back. Local cooperative custody is not cross-device author fencing.

## Functional proof and remaining work

The additive laws cover all four document/comment history pairs, actual seven-core
retirement, source-row preservation and concrete replacement participant recovery
with exact native histories and future Undo/Redo. They also cover first-capture
abort, an unsettled decision, decline, missing intent, stale current work, a
native-admitted older output, and failed real lease release followed by same-owner
retry and reacquisition of every source namespace. The final authority callback refuses a real attempt to change a suggestion retry
flag and leaves all seven writers live. A separate check changes that same queue
after the reservation is released and verifies that both a new and an already
admitted cut witness detect it. Both native histories and accepted content stay
unchanged, and the earlier preparation remains readable. Additional actual-Wasm laws cover metadata
retirement before and during admission, asynchronous adapter opening, active
read-only behavior and all independent native history pairs. A real revision
shutdown observer must receive a retired-source refusal without changing durable
queue rows. Existing cleanup laws retain their original assertions. The same laws are required in
source, offline-installed packages and the actual production bundle, with a private
strict type fence. Controlled failures are not physical power-loss qualification.

Replacement targets in these laws are opened explicitly through existing V3 host
APIs. The separate [whole-room execution intent](NATIVE_ROOM_EXECUTION.md) now
retains the complete root/catalog/asset namespace selection and both full asset
decision edges. A per-target execution journal, interrupted target replay and
whole-room handoff remain unimplemented. The separate [native actor handoff contract](NATIVE_ACTOR_HANDOFF.md) retains local
writer locks across failed target openings and synchronous cohort resource transfer.
It does not yet connect operational parents to a durable whole-room executor.
Those integrations remain architectural priorities before provider/client
reconciliation, compatible native union and authenticated serving activation. All
thirteen V1 gates and the full parity goal remain open.
