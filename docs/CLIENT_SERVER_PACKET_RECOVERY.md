# Client and complete server packet recovery

The source-owned metadata coordinator now has an additional
captureServerPacketRecovery(input) operation. Its closed input uses the genuine
continuation host, selected server archive, participant inventory and actual
asset transport already required by capturePacketRecovery. The original
client-only operation and all original files and diagnostics retain their meaning.

The new bundle family is breditor/selected-local-server-packet-recovery-bundle,
version 1, scope client-history-original-packets-complete-server-native-and-selected-files.
It contains the original complete packet-retention bundle, exact selected Native
server/inventory files, a separately hashed canonical server dependency response,
a new combined dependency result and, when complete, all raster bytes in a new
frame. Original source/reference/packet/receipt/retry records remain unchanged.

The actual cohort owner holds all seven source families and checks their Native
stamps during this finite capture. The server dependency collector uses private
host ports and genuine source checks before and after the entire capture. Its
selected source must equal the selected Native server archive. No parsed report
or copied host creates that source association.

## Complete dependency union

The combined result binds the exact reference-file and packet manifest pins,
the original packet Native identities and the complete selected server Native
inventory. When the original base history is Ready, each missing declared packet
can be covered by the same Native identity in that server inventory. A suggestion
can also be covered as the derived child named by a real original revision source.
Revision IDs alone are insufficient: their predecessor and child identities must
match. Repeated inert preparations remain separate source facts; coverage records
the first matching physical sequence and never interprets a preparation as a
committed publication or ACK.

The result is Ready only if the base history is complete, the entire server Native
inventory is Ready and every declared missing packet source is covered. Its
references are the bounded, unique union of all base, declared packet and complete
server Native causal/effect/physical-packet references, ordered by Rust UTF-8
identity order. A local-only unresolved packet remains Pending. Base-history
Pending also remains Pending; this operation does not erase its reasons or pretend
an uncached version was downloaded. The original packet Pending records remain
literal even when this separately named combined scope is Ready.

## Raster and file retention

The new asset frame family is breditor/client-and-server-native-packet-assets,
version 1, scope complete-client-server-native-and-whole-upload-raster-union.
Its parent pins include references, packets and dependencies. The older raster
reader rejects this family. The frame retains the complete Native reference union
and every whole origin/selected upload role. Actual provider mappings, immutable
PNG/JPEG/WebP bytes, hashes, dimensions and configured limits are checked. Missing
source, opaque mapping or bytes returns Pending while preserving the packet,
server/inventory and dependency files already captured. No held cache is changed
and no upload is acknowledged. A fresh complete provider read must still match
before success, and the genuine server source is checked again at the end.

The dependency response keeps its original 16 MiB response bound. Raster headers
are bounded at 16 MiB, chunks at 64 MiB and the complete raster frame at 1 GiB or
the smaller caller limits. Existing packet, catalog and local history limits stay
unchanged. Exceeding a complete-result bound refuses the capture rather than
returning a truncated complete result.

## Qualification scope

The [qualification record](qualification/2026-11-01-client-server-packet-recovery.json)
records 33/33 source cases and 33/33 independently installed cases with strict
public types. Both use the same frozen source, original Wasm and separately
pinned Native hosts. Both whole-cohort bundles preserve 17 first-server bodies,
82 local occurrences and four raster payloads, with exact disk readback and later
document/comment Undo/Redo across all seven families.

A separately compiled diagnostic using the existing Rust recovery API replayed
the exact saved server bytes from BOTH bundles into fresh inactive directories.
Each reproduced all 13 original physical packet sources and 15 Native asset
references exactly; every reference remains in the combined union. No service
started and no client owner was fabricated. A deliberately incomplete recorded
inventory passed DATA admission but was refused by actual Native comparison.
These diagnostics are retained with source, compile command and input/output
hashes; they are not an implemented production portable-inspection API.

Focused tests use seven actual saved Native readers lacking a newer accepted
proposal source. Their original packet read stays Pending while the complete
server inventory resolves the combined union and authenticated raster download.
These component readers are diagnostic Native cores, never fabricated operational
owners. Separate whole-cohort tests use the actual seven-family operational owner,
run the original packet recovery first and then the new capture, save/read every
Blob to disk, compare all packet/source/raster pins and preserve subsequent
document/review Undo/Redo checks. Independent installed-consumer tests use package
archives with no workspace links and strict public type checks.

Native server reconstruction and a source-owned portable inspector for this new
bundle remain required. Raw archive readers validate recorded framing, exact
bytes and declared consistency; they cannot certify reconstructed server Native
state, grant current provider rights, install client receipts, settle offline
work or activate a serving room. Independent comment/server-log generations,
complete reconciliation and authenticated whole-room activation remain in the
full V1 goal. No release profile or V1/parity completion is claimed here.
