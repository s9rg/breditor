# Coupled client and selected server recovery bytes

The private metadata owner exposes `captureRecoveryBytes(input)` and
`inspectRecoveryBytes(bundle, options)`. Capture accepts genuine controller,
transport, server archive and participant inventory instances. Its separately
named bundle contains the complete V2 Native/client/metadata/asset recovery
portion and the actual selected server and inventory file bytes.

The server and inventory must match the exact live controller's server tuple.
The inventory source must equal that server's Native selection. Source-host
capture uses the archived source point; a later server requires the original
genuine delivery-continuation controller and exact archived predecessor.
Readable data, a copied reader facade, matching rendered document text or a
different valid archive cannot supply this selection or lifetime.

The same parent quiescence covers actual source saves, review/metadata records,
all fourteen original/selected upload roles, Native before/stored/current
references, the V2 local/provider raster union and both selected server files.
Both whole files are hashed with the actual source-owned Native digest. The
controller is authenticated before and after these file reads. Every document
and comment source remains pinned. Disposing either supplied reader is observed
through captured class intrinsics; public method shadows cannot replace them.

Locally complete image uploads can remain Pending at the server. Those bytes
are retained under the V2 union scope without ACK, queue mutation or fabricated
storage references. A Pending Native/mapping/payload dependency never yields a
partial complete recovery bundle. All original V1 scopes and defaults remain.

Inspection first recomputes the exact archived client history and metadata cut
with genuine Native aliases, even if stored/live client state is newer. It then
matches the recorded server/inventory selections, independently hashes their
complete files and invokes the original selected-file frame readers. It uses
no network account and does not advance either journal. The result explicitly
describes a Native client cut and **recorded server byte selection**.

Server archive/frame admission is not a browser-side Native replay of a new
server, and historical unsigned controller data is not current authority. No
new writer, actor, provider, protected credential or serving role is created.
Accepted-head agreement, full provider/client reconciliation and authenticated
whole-room restoration/activation remain required operations.

Functional qualification covers an actual seven-participant room with three
metadata lanes and a locally durable image absent from the real server. A
second scenario publishes real document changes from another actual source,
observes Native server advancement, rejects the old archive pair for the newer
controller, and captures the exact new server/inventory through genuine Native
continuation. Fixture artifacts save every Blob role and inspect newly created
Blobs read back from disk. This fixture manifest is test evidence, not a new
public activation protocol. Component checks separately cover rehashed slot
corruption and selected-reader lifetime loss. No broader release or replay
claim follows from these tests alone; all V1/parity gates remain open.
