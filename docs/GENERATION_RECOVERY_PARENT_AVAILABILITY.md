# Generation recovery parent availability

The seven-family V3 recovery parent can check held histories and complete upload
stores against a genuine standalone generation control. Its origin/current
selection stays distinct from the physical A/B/C family. This supplies provider
availability while client parents remain held; it does not settle queues or
grant whole-room activation.

## Separate source and result contracts

The developer V3 method `readGenerationHistoryAssets` requires a branded
`SharedServerLogGenerationRecoveryHost` and independently supplied fresh history
read factories. It binds the catalog origin to the control's actual origin,
and the current archive and participant inventory to their exact selected values.
No ancestor or localOrigin alias is manufactured.

The result family is `breditor/server-generation-operation-v3-assets-read`
revision one. Its immutable `ServerGenerationOperationHistoryAssetsRead`
contains the generation control selection, original complete history read,
whole-upload pins and generation provider result. Existing `readHistoryAssets`
and its physical result retain their original contracts. The two host classes
cannot substitute for one another.

Both routes share a private history/provider projection. Family-specific source
admission precedes it; no supplied port or report becomes native authority through
the parent method. The developer V3 class retains its existing distribution scope.

## Complete native and upload borrow

The read holds the actual root plus original, generation, independent-local,
independent-delivery, restored-graph, local-operation-snapshot and
local-operation-flat parents. Each family keeps its current policy, native
history and complete source records rather than converting to an original-only
snapshot. Both document and comment history families stay explicit.

Every selected whole upload store is admitted under its own limits and pinned
by complete bytes, digest, metadata and actual target database. Immutable payload
metadata must agree across stores. The provider receives the native reference
union and all whole-upload IDs, including unreferenced bytes. A local uploaded
receipt cannot stand in for bytes absent from the actual provider.

Missing native dependencies or retained unselected catalog copies return Pending
with no subset provider proof. The genuine native control is still checked.
Missing provider mappings or bytes remain complete explicit requirements.
Checked means this availability read is complete, not registered-stream coverage,
comment binding, a save acknowledgement or permission to start delivery.

## Fresh policy and lifetime

The root reserves the operation before source selection or input inspection.
The generation route checks the actual host brand and source first, then detaches
read choices synchronously before cleanup awaits. Permission, signal or token
callbacks cannot retarget the request. Fresh read authority does not revive an
earlier editing job's grant or change current editing permissions.

All selected native parents and uploads are held before the first fresh grant
or operator callback. Actual root, catalog, current/pending source journals,
protected native records and whole uploads are reread after provider I/O. A
changed source or queue refuses even if an earlier phase or visible document
looked equal. Original protocol, history and packet meanings are unchanged.

Actual lock cleanup acknowledgements precede publication. Close, abort or cleanup
uncertainty refuses a prepared result and keeps the root busy until the borrow
ends. No native owner, upload store, writer lease or mutable core escapes in the
report. The read creates no target, uploads no image, rewrites no source, promotes
no queue, flushes no client, discards no historical copy and activates no service.

registrations under a standalone host. Its restored origin is newer than an
independently retained older server archive; its current physical cut extends
that origin. Native and provider checks use the actual source files and images.

The SDK matrix exercises five native grammars, two writer transports and four
independent document/comment history combinations. Each case reads all seven

document and comment Undo/Redo. Additional laws cover missing whole-upload bytes,
source admission, prototype substitution, partial selections, synchronous choice
detachment, root/catalog/upload tampering, all seven source journals,
cancellation, close and delayed cleanup acknowledgements.

Source and fresh offline installed-consumer checks also run the unchanged
physical provider laws. Installed and actual production-bundle paths repeat the
same assertions with only reversible module and fixture locations changed.
Node IndexedDB, lock and raster presentation fixtures are not physical durability
or native-browser evidence. The normal shared Wasm identity remains pinned.
