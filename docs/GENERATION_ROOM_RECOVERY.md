# Generation room inventory and custody

Generation participants retain native histories rather than exporting into the
original document-journal format. Room recovery must compare those histories with
an independently selected native server inventory and transfer all selected
participants together. Equal visible documents do not establish either property.

The prefix API is diagnostic reconciliation. The internal cohort transfer is a
prerequisite for operational generation room recovery; it is not an activation
API or a recovered authority grant. The additive
[V2 catalog](GENERATION_ROOM_CATALOG.md) retains mixed-family files and stages
private inactive owners. Original room catalog and participant APIs retain their
original formats and meanings.

## Reconcile native generation histories

Call `SharedRoomParticipantInventory.checkGenerationSources()` with genuine
`SharedGenerationParticipantBackup` and `SharedGenerationSourceCapture` pairs.
The method checks the actual native segmented checkpoint, schema, room,
principal, writer, transport and accepted document prefix. Paired review streams
also require the registered actor, binding, editing kind and accepted native
review prefix. Original suggestion, revision and version records use their
existing closed readers without converting the generation checkpoint.

The result uses the existing coverage contract. Missing or behind streams remain
pending; forked prefixes, wrong namespaces and duplicate copies refuse. A local
paired history without a server review binding remains `unbound_review`, not
covered. Permanent observers cannot contribute authored operations, while
historical work from a currently revoked author remains readable. Coverage does
not establish current permission, complete asset availability or reconciliation
of additional retained copies.

Native reads use a private, canonical facade. Caller-provided checkpoint objects
and copied identities cannot substitute for a live source capture. Reads perform
no storage, network, lease acquisition or document edits. The inventory and every
capture are checked again before returning the result.

## Separate readable history from managed ownership

Retiring a generation core leaves its history readable for backup and diagnosis.
It must nevertheless invalidate managed recovery and operational handoffs. Both
native and source registrations now check the actual core's private liveness
after the existing session admission checks. Final session checks use captured
canonical methods and reject shadowed core getters without invoking them.

This distinction repairs a reproduced fault: ready and operational handoffs, and
ready-to-operation admission, previously accepted an already retired core. The
regressions preserve readable original files, then reopen under fresh custody
and compare future native Undo/Redo.

## Transfer a cohort without partial escape

The internal coordinator accepts only genuine held operational generation
participants. It snapshots unique participant identifiers, rejects duplicate
owners, and marks all children busy before awaited verification. It then verifies
retained originals, native ancestry and every actual upload owner.

Coordination leases are released together. A release failure consumes no child
and permits retry. Once release succeeds, individual handoffs are cleanup-only;
only the room capsule can commit. The [common barrier](OPERATIONAL_COHORT_CUSTODY.md)
checks native cuts and current policy, disposes temporary native readers, then
rechecks current policy, source cuts and managed-source/upload liveness before
consuming any child. No native destructor, await or application callback occurs
during consumption. A late refusal returns no participant and retains committed
files for fresh cold resume. Original, generation and mixed-family adapters,
and individual operational transfers, share these phases.

The native matrix covers ten profile/transport fixtures, local/relay/retained
families, two participants and eight success/failure paths per cohort. It checks
exact committed records and original files, all upload entries, cold reopening
and future document/review history. IndexedDB, coordination locks and raster
decoding are controlled fixtures; this does not qualify browser crash durability.

## Remaining room recovery work

The V2 catalog retains the selected native server bundle, inventory and every
supplied participant file using a separate closed manifest and durable inactive
staging records. The [durable V2 operational parent](MIXED_ROOM_OPERATIONAL_RECOVERY.md)
records the mixed-family recovery intent, supports cold resume and transfers
both families together with their original journals and Undo histories.
Explicit dispositions for other retained copies remain open.

Independent comment/server-log generations, complete client/provider reference
closure and current authenticated whole-room activation remain separate required
steps. Successful prefix checks and a cohort handoff do not satisfy them.

## Required checks

Both candidate profiles include `generation-room-inventory`,
`generation-room-custody`, `operation-cohort-contracts`, `mixed-room-custody`
and `installed-generation-room`. Their native fixtures
are built normally from the current source. Fresh offline archives repeat the
same native probe assertions with bare public package imports; internal
installed-file hooks are identified as fixture hooks. The existing generation
asset suite retains its prior assertions and adds the retired-core and
callback-free source-admission cases.
