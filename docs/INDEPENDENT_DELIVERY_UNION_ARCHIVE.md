# Durable independent delivery participant union

Breditor can retain a compatible participant union as one immutable archive before creating a replacement source or upload store. The archive preserves both complete original participant backups, an explicit whole-upload decision and a rebuilt ordinary participant backup. Cold admission recomputes the native, packet and raster result instead of trusting a ready marker or output hash alone.

This is the durable participant layer of the [source union](INDEPENDENT_DELIVERY_BRANCH_UNION.md), not authenticated whole-room activation. Its output uses the existing independent-delivery participant format and existing absent-only recovery coordinator. Ordinary strict room reconstruction and execution contracts remain unchanged.

## Complete original inputs and output

Both original files keep their native document/comment lanes, local Undo/Redo histories, local immutable versions, suggestion/revision/version stores, raster bindings and complete upload queues. Preparation uses private read-only native copies and never replaces live adapter caches. Original comment role/prefix windows must be supplied independently on build and every cold semantic admission; the archive contains no reusable permission grant.

The output includes every native-history and retained-packet raster reference, including images hidden now but needed by future Redo or an incoming peer update. Raster identity conflicts refuse. Two different payloads at one opaque immutable identity cannot be resolved by branch arrival order. Uncached catalog packets and missing raster bytes remain explicit pending dependencies rather than being omitted from a ready result.

All conflicting whole-upload states require explicit current/original choices through the existing reconciled-asset-base contract. Pending, failed, cancelled and uploaded records remain complete; epochs and retry counters do not order two copies. Both losing files remain in the archive even when the selected output chooses one state. Stored upload receipts are retained data, not newly authenticated provider receipts.

## Explicit manifest identity

The new choice identifies exact total bytes and manifestSha256, the SHA-256 of the canonical manifest. Each of four named components has its own complete SHA-256 pin. Cold admission checks fixed framing, canonical header bytes, every component hash and exact final extent; trailing bytes and modified bodies refuse. This selection is deliberately not a whole-file SHA-256 field.

The outer budget covers three complete existing maximum participant files, a full three-sided asset decision and framing. Component hashing keeps the existing one-GiB native digest ceiling and one-MiB chunk size unchanged. The larger outer file does not shrink old component capacities or enlarge an old digest protocol. Existing participant/raster codecs retain their own limits and allocation behavior. Maximum-size memory, quota and performance qualification remains separate.

## Immutable preparation and cold reopen

The explicit layout names four distinct future namespaces: the union journal, ordinary recovery attempt, replacement source and replacement uploads. DATA construction opens none. prepareSharedIndependentDeliveryUnion saves only the journal, in one absent-only upgrade transaction. readPreparedSharedIndependentDeliveryUnion opens only an existing exact journal; a missing read aborts creation. Count-first reads reject extra rows before loading retained blobs, and a foreign database is never overwritten.

Every boundary freshly checks native/store admission, the exact asset decision and current host policy. Policy checks must return undefined synchronously; a boolean or Promise is not approval. Storage context and lock identity are pinned before callbacks can run. Abort cleans private readers and eventual unclaimed native owners; a queued IndexedDB open retains real cleanup until its late upgrade becomes terminal.

A lost completion after a committed journal leaves the complete archive available for an exact cold reopen. Ordinary participant recovery then writes both native lanes, dependent stores and whole selected uploads into separately authorized absent destinations. Interrupted source or upload writes use that coordinator's existing exact-adoption rules. The original union journal remains unchanged throughout.

## Room integration and remaining work

The output is an ordinary recovery input, not actor custody, a provider grant or a serving credential. The complete room workflow still must bind this new union provenance into its preparation/retirement/execution plan, preserve actual author locks and authenticate cross-device activation. All seven operational source families are not yet qualified for union mutation. Unknown local-author histories, incomparable sealed branches and conflicting user intents still need explicit resolution; old strict continuation is not relaxed to bypass them. All thirteen V1 gates remain open.
