# Continue execution with actual retired actor custody

The SDK-private `RoomExecutionAttempt.beginRetired` and `resumeRetired` entries
continue a genuine same-scope retirement without releasing or reacquiring its
writers. They require the actual closed selected owner and its branded reserved
actor execution object. A saved phase, receipt, copied reservation or still-live
owner cannot select this route. Ordinary `begin`, `resume` and retirement keep
their existing contracts.

The same-scope retirement inspector now pins the complete exact preparation on
that actual reservation after checking all recipes, current source/upload bytes
and fresh approval. Final retirement still belongs to the original owner and
its final witness. Transfer refuses until that owner really is closed with the
actual stopped actor cohort retained. One approved preparation is immutable for
that reservation; changing it requires an explicit new attempt while originals
are still live, rather than overwriting an approved binding.

Before reflecting on constructor inputs, a private synchronous transfer replaces
the old token and revokes the old reservation. The actual actor cohort remains
in the same closed root. Caller proxy traps therefore cannot take actors or
release the replacement's writer locks. The constructor compares its admitted
execution preparation with the exact pinned preparation. Any refusal restores
the original token and reservation synchronously; no asynchronous constructor
can hide moved actors. Successful construction commits the transfer only after
the replacement attempt is fully initialized. No fallible application callback
runs between that commit and its synchronous return to the caller.

The already-returned attempt takes the actual cohort during `run`. Existing
complete execution admission, private target recovery, selected upload checks,
fresh promotion approval and the final root/actor barrier still run. Neither a
returned local target result nor a saved journal grants remote serving.

The functional case exercises all seven actual source families and fourteen
writer locks. It refuses a different structurally admitted preparation, rejects
live/data-only custody, restores custody after input-reflection failure, denies
old-reservation reentry and promotes a usable local successor with zero ordinary
writer reacquisitions. Native checkpoints initially match; future document and
comment Undo/Redo restores exact content/views for every client. A new caret edit
works after promotion, while all original source store bytes remain unchanged.

Qualification deliberately preserves a test setup failure. Both earlier combined
ten-case runs passed nine cases and failed the final typing assertion because
the test had restored a range without placing a caret. An independently staged
full case passed with an explicit caret. The final two new cases then run again
from source and fresh installed archives. Eight unchanged regression cases from
the earlier worksets remain retained; the combined ten-case wrapper was not
rerun after the test-only correction. Every runtime source file and installed
distribution byte is checked unchanged across that correction. Strict source
and fresh installed declaration checks keep these entries private.

The proof retains both exact source versions, original failures, corrected
assertions, actual Native fixtures, archives and compressed read-back-verified
objects. IndexedDB and actor locks are controlled Node fixtures. This does not
qualify browser-storage crashes or a complete platform/policy matrix. Rust,
normal Wasm, versions, original protocols/defaults and public root exports stay
unchanged.

A persistent joint activation attempt must still hold the genuine source lifetime
through uncertain Native commit outcomes, coordinate local retirement/replacement
and publish normal server routes under fresh host authority. This checkpoint
supplies the actual retirement-to-executor custody transfer; it does not complete
