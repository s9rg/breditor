# Authenticated mixed room recovery

Mixed-room recovery can fetch original accepted comment permissions from a genuine independently selected native server, then use them in the existing native union, execution, retirement and local actor-handoff paths. A saved server reply or caller-supplied permission window cannot replace that live authentication. The original caller-window APIs, serialized identities, journals and native protocols keep their meanings and defaults.

The authenticated entry points are SDK-private and explicit. They do not promote the optional packages, activate remote serving or establish complete provider and client reconciliation. Current recipient permissions remain separately chosen host policy; historical source roles never become a recipient's current role.

## Selection and original permissions

NativeRoomUnionAuthenticationOptions contains a genuine SharedPhysicalRoomRecoveryHost and one originalReview query for every participant using independent-delivery-union mode. Each query has a member ID and the existing independently selected review binding and canonical actor/account/counter ranges. Missing, duplicate and extra members refuse. Original continuation members cannot silently enter union mode.

Data choices detach before asynchronous work. Each admitted current and retained room catalog must match the host's ancestor, selected server and complete participant-inventory identities. The actual held current owner must still pass the ordinary complete-cohort, native, retained-packet and upload checks. Matching metadata does not manufacture that owner.

Each relevant admission obtains fresh original permissions through the private branded host port and the existing original-review endpoint. Native replay verifies the returned prefix witnesses and every incoming event. No JavaScript document merge or lineage reconstruction replaces it. Independent document/comment histories, local offline suffixes, both literal room inputs and future Undo and Redo remain with their ordinary native owners.

If any requested range remains unknown, observing or unaccepted, NativeRoomUnionOriginalRightsPending rejects the complete attempt. Its pending list contains only unresolved member reads, whose permission windows are empty. No partial permission set reaches branch preparation. Omitting an unknown actor from the query does not bypass native verification of an incoming event from that actor.

The authenticated path reuses the existing concrete storage, ownership and native-replay coordinators:

- retireAuthenticatedNativeRoomUnionKeepingActors and its reserved counterpart fetch fresh rights while the genuine original cohort remains held. After the new affirmative decision and exact final cut, another actual host check precedes retirement.
- NativeRoomUnionExecutionAttempt.beginAuthenticated and resumeAuthenticated keep the same real reservation, progress journal, stopped actors, partial targets and successor recipient. Each run/retry and promotion admission reauthenticates. Final handoff authentication occurs while the existing common native/packet/asset/actor witness is still held.
- ColdNativeRoomUnionExecutionAttempt.resumeAuthenticated authenticates before fresh actor acquisition. The original entry points still require their original authorizations field and reject the new authentication field. Authenticated choices reject supplied authorizations. Neither family silently chooses the other.

## Failure and ownership

An attempt is synchronously reachable before it can move actor resources. Missing or denied authentication before retirement leaves the actual original writers usable. Failed target writes retain the real actors and partial targets in the same returned attempt. Explicit close drains those borrowers before releasing actor custody, so a later cold attempt must acquire all actors afresh.

Once admitted, the actual run journal is part of every nested warm/cold read and handoff liveness guard, not only a check before network I/O. A real version-change during final authentication must refuse before publishing ready state or crossing the common handoff. Failed journal openings are not prematurely admitted into that parent guard: their actual cleanup handle remains reachable for close/retry. Cleanup-only completion can detach an already owned journal without requiring a new historical grant.

The common handoff still transfers actual resources into an already existing recipient before completion I/O. Cleanup-only complete and one-shot take do not repeat the transfer or require a new historical permission grant. They must remain usable for already-owned local resources after an operator check stops. The independently supplied recipient and asset policies govern future editing after the old read job closes.

Immutable preparation/execution intents and uncertain completion keep their original exact-data recovery rules. A late failed check cannot turn a saved phase into permission or erase an already committed data file. All unresolved original inputs remain available for a newly authenticated attempt.

## Bounded authentication and request cleanup

There are at most 1024 member queries. Their normalized complete collection is limited to 16 MiB, matching the existing mixed-room header budget. Complete authenticated replies are counted incrementally against another 16 MiB collection budget before their windows or pending entries accumulate. A member's native and HTTP limits remain unchanged. These are byte/count bounds, not a maximum-latency qualification.

The physical control host reserves its real busy slot before input reflection, signal setup or callbacks. Signal installation and response cleanup run inside that lifetime. Genuine event-listener methods and the native cancellation-state getter avoid overridden per-signal hooks. Setup/cleanup failures release the reservation, cancel available unread response data and return a bounded control error; actual asynchronous stream cleanup retains the reservation until it settles.

## Remaining whole room and release requirements

This authenticates accepted historical rights through the supported mixed-room local workflows. It does not attest roles for events the server has never accepted, merge unknown own-author suffixes or implement union mutation for every source family. Other families retain their strict continuation requirements. The authenticated SDK path requires the existing physical control-host family; it does not implicitly admit independent server comment/log-generation control lifecycles. Those end-to-end lifecycle joins remain open.

Complete registered native streams, declared and historic client copies, retained packets, outboxes and provider bytes must still converge at one current server cut. Remote serving activation must validate that complete cut while excluding old accepted writes, then claim the genuine deployment authority. A live permission read or successful local handoff cannot replace that boundary.

The focused qualification commands are scripts/check-authenticated-room-union-native.mjs, scripts/check-authenticated-room-union-sdk.mjs and scripts/check-authenticated-room-union-installed.mjs. The SDK workload retains both complete predecessor workloads, counting their exact shared branch files once, and adds the new authenticated/lifetime/budget/refusal checks. Native HTTP and the normal Wasm are real; Node storage, locks and raster presentation are controlled fixtures. Physical crash, browser, full release-corpus and public deployment qualification remain separate. All thirteen V1 gates and full feature parity remain open.
