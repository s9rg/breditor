# Retained native continuation

Retained native continuation keeps the genuine native sessions and origin-upload
custody available after a temporary complete-record reader closes. It is an
SDK-private prerequisite for editable selected-asset succession, not a public
owner constructor, writer grant or completed successor.

## Same complete cut and actual sessions

The private room coordinator reserves every selected genuine parent before fresh
host callbacks. The existing fresh history readers admit the actual native,
packet, journal and literal-input records; whole-upload custody is held at the
same time. The continuation borrows those exact sources from that reservation.
It does not restore checkpoints into substitute owners or copy a document AST.

Every retained client is the existing SDK native instance. The complete portable
cut still retains committed, pending and attempted saves, literal inputs and
whole uploads. A separate LIVE comparison binds the current document/comment
histories, selected packet stores and native access policy. That comparison is
not a replacement for the full cut.

Ordinary record access correctly refuses while a complete-record reader owns a
typed read gate. The bridge therefore retains the held LIVE values and private
native/policy stamps through actual reader cleanup. Once the real cleanup has
finished, it creates an independent source witness and compares it exactly with
those retained values. A document, comment, packet or policy change across that
boundary refuses before the retained result escapes. Managed source bindings,
actual parent namespace leases and storage changes remain checked.

## Grants and lifetimes

A fresh read grant does not reuse an expired whole-room recovery-job grant or
its cancelled signal. It also does not renew participant write permission.
Long-lived native writers keep their independently supplied participant policies;
a later owner must have appropriate current writer authority before exposing
editing. Readability, stored approval and native history are not that authority.

Closing a retained reader never closes its actual parent sessions. Closing it
before temporary-reader cleanup finishes refuses. Failed cleanup retains the
actual resource closures for retry rather than abandoning pending work.

## Exact inherited origin custody

The original and generation families use temporary whole-upload exclusion; the
other five families already retain their own origin custody. A retained reader
can donate only its genuine legacy origin custody. Donation ends that reader's
capability and keeps the actual lock callbacks owned by the receiving SDK code.
It does not consume the native parents or approve a new asset baseline.

A subsequent complete-record read can borrow this exclusion only when its actual
store objects match the privately registered token, in order. Saved database
names, copied methods, detached facades and a genuine token for unrelated stores
cannot substitute. Temporary-reader cleanup does not release borrowed custody;
its real owner remains responsible for closing and awaiting the lock callbacks.
This permits future current captures without deadlocking on reacquisition or
temporarily exposing the origin stores to mutation.

The selected active asset stores remain a different contract. Neither donation
nor capture swaps the upload pointer or weakens the old receipt, immutable-byte
or monotonic-attempt rules.

## Functional qualification

The normal stages are `retained-native-continuation-contracts`,
`retained-native-continuation-type-fence`, `retained-native-continuation` and
`installed-retained-native-continuation`. The cumulative workload retains all
1,554 prior laws and adds seven capability/data laws and eleven actual-native
scenarios. Four independent document/comment history pairs cover all seven
families, cold native recovery and future Undo/Redo. Refusal, post-cleanup
mutation, current capture and actual-store identity have separate cases.
The package-root type fence keeps these implementation capabilities private.

The [retained qualification](qualification/2026-10-24-retained-native-continuation.json)
passes eighteen selected normal stages. Source, independently installed offline
packages and the actual production bundle each pass 1,572 cumulative assertions
with no failures, skips or cancellations. Twenty-one strict consumer fixtures
keep the implementation capabilities private. Both native producers supplied
100 fresh source-pinned files, and all sixty test-owned control ports are closed.
The normal Wasm, package versions and public-root runtime names are unchanged.
Controlled storage, locks and raster fixtures do not qualify physical crash
durability or platform behavior.

Native parent consumption and a common root-plus-stage ownership barrier remain
required. The editable successor also needs an explicit selected asset baseline,
durable intent, current capture and cold resume after new edits. Complete
provider/retained-copy/registered-stream reconciliation, authenticated activation,
stale-writer fencing, sustainable history and remaining functional parity follow.
All thirteen V1 gates remain open.
