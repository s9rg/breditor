# Warm room ownership promotion

The private warm executor can promote its staged native replacements and selected
uploads into one usable local owner. Native history, dependent review packets,
actual source parents, complete selected queues and all retained actor locks move
through the same final handoff. Local succession grants neither a provider save
acknowledgement nor authenticated server activation.

## Separate fresh decision

After `run` stages the room, `previewPromotion` returns joint DATA: the
exact execution identity, current journal head and complete root/asset approval
choice. `promote` independently reads the immutable intent and journal again,
rechecks the real current cut, matches that choice, and obtains a fresh affirmative
decision. Saved readiness or a previous approval never supplies this decision.

Promotion reserves the actual attempt before reflecting caller input: JavaScript
proxy hooks cannot enter a second preview, run, take or promotion during capture.
Refusing a busy call cannot clear another operation's real reservation. Close
remains the explicit cancellation/cleanup route.

The final approval uses the explicitly planned approval database. Its existing
format retains the complete native/source/packet cut and every full selected base.
An exact committed file can resolve a lost completion; a different file is never
overwritten. The execution intent and journal keep their original schemas and
stage meanings. The last journal stage remains advisory, not a serving flag.

## One actual ownership barrier

The root reserves its actual children and selected stores while reading the full
cut and retaining the approval. Actual journal cleanup finishes before the final
barrier. A failed close keeps its real handle in the same attempt, marked for
cleanup retry before an existing-only reopen. The old closed owner's reservation
can then release without releasing any actor lock held by the attempt.

Temporary source readers really close before a fresh selected-store readback.
After all application callbacks, native and packet witnesses check the unchanged
complete LIVE state and actual origin custody. The final actor check pairs the
root with its genuine cohort and verifies every final source core against its
exact constructor-owned loan handles. Only then does the whole actor cohort
promote, followed synchronously by parent, root and selected-owner flag changes.
No await, application callback, storage request or native destructor splits this
ownership move. Ordinary retained-root and asset transfers do not promote actors.

## Reachable successor and one shot take

The attempt owns a private recipient before promotion starts. The new owner is
placed there while inactive, before any parent changes ownership. Successful
activation changes only private flags. If a later asynchronous return rejects,
the real owner remains reachable through this same recipient rather than being
hidden in a rejected Promise.

The promotion result is DATA. `takeOwner` synchronously transfers the actual
active owner once. Old read-job cleanup runs while the recipient still owns it;
only then is the reference taken. The take itself reserves the attempt before
cleanup can fire synchronous abort observers. Nested takes refuse as busy; a
callback Close cancels the move while the recipient still owns the successor.
Ending or aborting that completed finite job
does not become the returned native or selected-asset permission. Participant
policies and the explicitly selected asset-access callback govern their separate
lifetimes. The new owner can edit, use native document/comment Undo and Redo,
capture complete current state, and retain new pending uploads under those grants.

Closing an unclaimed promoted attempt closes its actual successor before actor
cleanup. Closing an attempt after take cannot close the transferred owner. Neither
Close path deletes source, target, journal or approval bytes. Cleanup publishes
its actual Promise before synchronous abort observers run, so reentrant Close
calls join the same operation over the genuine reservation. An interrupted
pre-barrier attempt retains its actual handles and needs fresh approval to retry.

## Remaining recovery and activation

This is the warm path from a genuinely reserved current original owner, not full
process recovery. A new process must independently admit complete current target
state and acquire real actor locks. [Fresh actor recovery](COLD_ROOM_RECOVERY.md)
now provides that path for a complete existing selected room and independently
kept basis. Interrupted execution before such a root exists remains separate. A
stored ready or approval record cannot stand in for real current custody.

Compatible native union, dependent-packet and provider/client reconciliation,
independent comment and server-log generations, authenticated whole-room
activation, sustainable Undo/offline/asset retention and full release matrices
remain part of the V1 parity goal. All thirteen release gates remain open.
