# Metadata namespace continuation

This private SDK action continues the original review and metadata journals into
an actual replacement room. It is an experimental component; it does not approve V1, activate
a server, publish a room, or provide physical-storage durability evidence.

The original same-namespace restore and exact-generation preparation keep their
existing contracts. Relocation uses a separately named
`breditor/selected-local-metadata-continuation` choice. Its complete immutable
intent retains the original prepared room, current room, review journal and
metadata journal before any destination is constructed. Hashes bind every byte.

## Actual replacement ownership

`RoomExecutionAttempt` keeps the promoted successor private during each metadata
operation. A same-visit runtime witness binds its real execution identity and the
complete physical cut admitted by promotion. A saved choice, copied inspection,
matching text or writer identifiers cannot create that witness. Owner transfer
and concurrent metadata operations refuse while the visit is active.

Admission replays the original review and metadata histories using the actual
constructor-selected read factories. Every local lane must preserve its original
history prefix, versions, immutable packets and authenticated receipt facts in the
actual replacement source. The full target cut must still equal the cut admitted
by promotion. Reconstruction may preserve a legitimate union of offline branches;
it need not falsely claim that the replacement is byte-identical to the old room.

## New bindings and literal old facts

The old before/current journals remain unchanged and are retained literally in
the intent. The new review baseline describes the actual replacement source. The
new metadata baseline retains the original initial local records. Only after full
Native admission can one-shot same-visit proof tokens install the original current
review receipts and metadata records into genuine runtime stores. This explicitly
creates a new binding without rewriting the historical baseline.

The destination runtime re-admits packets, enforces forward progress and uses the
existing full-record compare-and-swap writes. Metadata continuation also checks
the actual parent's saved review facts. Pending packets stay pending; old receipts
remain the same receipts. This action does not invent new delivery acknowledgements
or silently turn missing current-generation evidence into accepted metadata.

Fresh preparation uses the real previous/current delivery control and its actual
participant inventory. It is a separately named advanced-inventory route; the
original exact-cut generation-provider admission is unchanged. No transports or
editing callbacks are started by continuation.

## Failure and retry

All four destination names must differ and may not overlap the actual original
or replacement room storage. Initial creation is absent-only. Explicit resume
requires the existing complete immutable intent, the same actual private target,
current controls, full re-admission and a new affirmative decision. Destination
journals may be absent, at the exact initial state, or contain the exact original
facts already installed. Unrelated later data is preserved and refused.

The intent remains retained after interrupted writes or refused completion. Late
IndexedDB opens remain owned until their actual terminal event; cancellation does
not release custody early or leave a successful late placeholder. Cleanup tries
every owned resource and retains the original failure if cleanup also fails.

## Remaining integration

The joint coordinator must bind the original metadata file pins to its actual
retained source/activation capture before calling this private action. Native
history and packet admission alone do not turn arbitrary historical ACK-shaped
DATA into a newly observed server acknowledgement. Keep this component private
until the complete joint contract supplies that association.

This component must still be composed with genuine Native epoch commit,
uninterrupted actor custody, production authenticated route publication and cold
recovery of the whole joint operation. Three local metadata lanes and seven
source/replacement families require the same functional evidence from source and
independently installed packages. Physical browser storage, the complete history
policy matrix, remaining parity and all thirteen V1 gates remain separate work.
