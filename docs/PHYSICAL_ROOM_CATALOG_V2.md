# Five family physical room catalog

The private version-two physical catalog retains independently selected complete
server files and original, generation, independent-local, independent-delivery
and restored-graph client archives. It reopens actual immutable bytes and native
graph data without selecting a historic writer copy or manufacturing a delivery
binding. It is file retention and prefix diagnostics, not editable participant
adoption or permission to activate a replacement server.

## Explicit version and namespace

The canonical manifest selects `breditor/shared-physical-room-recovery-catalog`
version 2. Every child file keeps its original format and exact byte digest.
Old physical catalogs remain version 1 with their original two-family contract;
neither reader silently adopts the other version.

The durable database starts at schema version 1 with only
`physical_room_v2_state` and `physical_room_v2_files`. Its immutable sole state
record selects `breditor/shared-physical-room-recovery-state` version 2 and the
complete canonical manifest. No native-ready, disposition or activation flag is
stored. The separate names prevent a version-one catalog database from being
upgraded, overwritten or mistaken for a new destination.

`PhysicalRoomCatalogV2Archive` admits data through the actual canonical child
readers. `PhysicalRoomCatalogV2.begin` requires that genuine archive and an
independently retained selection, then atomically retains files only in an absent
database. An occupied destination requires explicit `resume`; a missing archive
cannot turn Begin into Resume. Both reopen and re-admit actual durable files
before returning a runtime owner. These classes are not package-root exports.

## Independent selections and read factories

Origin and current complete native/server selections retain the existing closed
identity readers. The inventory must name the exact selected current native
archive, including physical-only changes. Matching declarations are necessary
file consistency, not native host ancestry or current service authentication.

Every restored graph additionally requires an explicit `graphPolicies` row with
its catalog ID, independently selected original participant and fresh native read
options. The file never chooses executable factories, read permissions or grants.
Duplicate, omitted or unrelated graph policies refuse. Read grants are separate
from the writer grants embedded in historical operation provenance.

Inputs are snapshotted before awaited byte or storage work. File/policy rows use
one bounded indexed array shape; caller map, iteration, species and later lengths
cannot alter traversal. Complete native identities are normalized before Blob
callbacks. Graph factories are snapshotted before payload callbacks can retarget
their source options. A synchronous native/read callback cannot acquire the same
catalog namespace while its actual opening reservation is held.

## Actual archive ownership and current checks

Native graph admission performs the existing genuine document/comment replay,
continuation and asset checks. Other family files use their unchanged complete
archive readers. No local history is wrapped in an invented delivery object.
Canonical dispatch ignores mutable class facades. Admission checks the current
host policy and signals at its asynchronous boundaries; native graph replay also
carries the enclosing catalog guard and the separately selected graph read grant.

The catalog owns an actual archive, database connection, database factory, lock
manager and cooperative recovery lease. Storage context cannot be retargeted
across awaits or callbacks. `verify` reserves its wait handle before callbacks,
rereads one coherent database transaction and re-admits every complete file.
Stored row counts are checked before file value cloning. Changed schema, extra
keys, missing data, changed manifests or bad child bytes refuse without repair.

`checkSources` is a separate cached diagnostic with no storage transaction or
network request. It checks explicit selected IDs against the actual stored child
archives and genuine native source captures. A graph reopened from the catalog
needs a fresh native borrow against that actual graph handle; an old handle or a
readiness-shaped object cannot replace it. Prefix results retain the full current
physical source selection.

All omitted historical copies remain retained and unresolved. Local comment
histories stay explicitly unbound and Pending, including in an otherwise complete
selection. Duplicate selected IDs or native writer/actor copies refuse; no copy
is chosen, discarded, rebound or made eligible for deletion. `checked` is not
provider availability, complete outbox reconciliation or an activation grant.

## Transfer and cleanup

The private transfer friend requires the actual catalog brand. It reserves before
callbacks and verifies retained files before and after successor preparation. One
final synchronous commit transfers the same archive, database and lease; the
source retires without destroying them. Closing that old source or revoking its
old policy afterward cannot destroy the successor's actual resource custody.
The successor must supply its own current policy and native staging contract.

Close waits for verification or transfer. It releases actual resources without
deleting any durable file. A failed release remains reachable for retry, and
competing opens stay excluded until it succeeds. Cleanup for an unreturned failed
opening remains recorded in the actual factory and namespace and is drained there
before a retry. A late post-commit policy refusal preserves the committed files
for explicit Resume; it never overwrites them with an older cut.

## Bounds and qualification

The file table retains the existing 4,096-file, 16 MiB manifest and 16 GiB aggregate
declared envelope. Child archive/native limits remain unchanged. Diagnostics
separately admit at most 1,024 selected sources. These are admission bounds, not
approved memory, latency, quota or physical-durability envelopes. Full graph
admission still scales with retained native histories and inputs.

The mandatory source and fresh offline installed probes cover ten native
profile/transport rooms, four independent document/comment policy pairs, six
older source kinds and both author directions. Each fixed 480-cohort matrix must
check 2,400 historical copies, 4,800 exact cold files, 1,920 fresh actual graph
borrows and the explicit local Pending cases. Focused laws separately cover native
family combinations, policy denial, corruption, bounded reads, callback binding,
namespace reentry, schema isolation, actual transfer and cleanup retry. Installed
assertions may change only module/runtime/native fixture data locations.

Actual five-family participant staging and operational adoption remain separate.
The [complete local-only coordinator](INDEPENDENT_PARTICIPANT_RECOVERY.md) now
exists, but its resources are not automatically adopted into this catalog. Complete provider
and client/outbox reconciliation, every historic copy's disposition, fresh
authenticated activation and sustainable Undo retention remain required. No public
room API or V1 release gate is promoted by this data component.
