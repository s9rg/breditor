# Real native delivery service fixture

This is a functional integration fixture for the full V1 recovery goal, not a
new editor protocol or whole-room activation API. The production Rust library,
ordinary Wasm, source families and persistence defaults are unchanged.

## Native ownership and activation

The selected_delivery_functional example binds its real loopback client and
retired-source sockets before any SDK source is created. It registers seven
actual native document/review author pairs, each with an accepted prefix and an
outstanding offline suffix. Document, comment and physical server-log generation
boundaries remain independent. Two actual PNG assets are retained.

The original serving owner is deployment-epoch fenced and sealed by the existing
durable source-handover contract. Its original router stays alive to test actual
retirement refusals. The distinct target is prepared, its protected author
streams verified, its activation choice saved absent-only and its durable native
service activated through the existing public server API. No unfenced alternate
room is opened to make the fixture pass.

Each fresh operator snapshot captures the actual currently serving target,
verifies all fourteen original protected streams and its raster provider, and
uses a separately authenticated operator endpoint. Client and retired-source
endpoints do not change. Earlier snapshot files are never overwritten. Offline
client seeds in those files remain the original immutable seeds, not fabricated
newly reconciled client state.

## Private authentication

The host generates distinct source/target account tokens, actual native writer
resume credentials and a separate operator token. Credentials pass only through
the inherited private parent/child pipes. The bounded fixture IPC is not a public
HTTP route and does not turn archive fields into authority.

The JavaScript fixture requires an exact original writer/actor pair before asking
the native host for its credentials. It does not infer account authority from
decoded checkpoints. Public files are checked for generated secrets. Private
replies are neither persisted nor printed in qualification reports. Fixture
directories and files use the existing absent-only private storage contract.

## Executed public workflow

scripts/probe-selected-delivery.mjs is the same public-API workflow in source,
fresh offline-installed package archives and the executed minified SDK bundle.
It requires all ten original native grammar/wire modes. Every mode verifies all
seven original offline document/comment authors, actual raster bytes, target
authentication, refusal of retired credentials at the target, refusal by the
actual sealed old service, real durable receipts, reconnect without duplicate
submission, future native Undo/Redo in both lanes and exact paired cold reopen.

Actual delivery changes the server cut. The old exact operator check must then
refuse; a fresh authenticated snapshot must accept the new cut. This is important
evidence for the coordinator: refreshing a scalar selection is not complete
adoption of advanced client, packet, asset and server state.

Both candidate profiles require the example build, the source matrix, and fresh
installed/bundled execution. The installed check rejects workspace links and
registry artifact drift, checks strict public type boundaries, and records the
exact package, production bundle, native host and normal Wasm identities. The
test harness alone provides synthetic Node IndexedDB, locks and image decoding;
none of those claim physical browser durability.

## Still required

The separately isolated held-owner SDK prototype can use this fixture with the
same actual seven-family retained owner, not newly reconstructed replacement
sources. Its four already-bound families can deliver through the real target.
That development test is not merged or an installed/public API qualification.

Three genuinely unbound local families still need explicit adoption. Metadata
outboxes need real constructor-owned transport/token custody and receipt-backed
transitions. A durable coordinator must save the complete prepared before-cut
before authentication/resume/submit, retain partial factual outcomes, read them
back for retry, reconcile the advanced actual server/provider cut and activate
the whole room without losing outstanding offline edits, Undo/Redo, review
packets or assets. Do not weaken old reconstruction equality to disguise those
missing transitions. All thirteen V1 gates remain open.
