# Selected local review data restoration

Status: SDK-private implementation. Qualification is recorded separately; all thirteen V1 gates remain open.

The separate restore entry point copies the complete new layer's immutable original preparation file and full before/current receipt records into their original two namespaces. It requires the complete multipart bundle and a genuine already reconstructed selected-room scope. Both native histories, immutable packets, complete source/asset cuts and an authenticated full server path are checked before and after a fresh host decision. A hash, matching final text or actor name is insufficient. Underlying source/native/upload databases are not manufactured from an AST by this API.

The restore choice pins the literal preparation and delivery identities, portable receipt bytes/hash, current actual room cut, complete native path and each destination's observed disposition: absent or identical. Probes abort missing upgrades, leaving no empty database. Both namespaces are cooperatively reserved before approval. Existing records must match every selected original byte; conflicting data is refused without overwrite. Database names and original protocol meanings remain unchanged.

IndexedDB cannot atomically commit across two databases. Each database is copied atomically and read-verified. A failed second copy leaves the first committed copy intact. A new preview exposes identical/absent and requires a new decision; the old absent/absent choice is stale. A later policy refusal never erases committed facts. Pending requests and late reservation/completion callbacks remain owned through cleanup; a busy cleanup retains exclusion until its actual request can drain.

Restoration returns data only. It does not create a prepared gate, authenticate an actor, select a writer, revive an old grant or activate a room. The normal existing-only cold-resume entry point must separately revalidate current native/server/source continuation, obtain fresh current approval and create a new gate. The original document/review adapters then authenticate and check real batch receipts again.

The functional test uses the real native service and normal Wasm. It cold-reopens all seven underlying source families, preserves their new offline document/comment suffixes, simulates loss of only the two fixture metadata databases, rejects corrupted input and a denied decision, injects a real second-upgrade failure, retries from its literal first commit, resumes normally and obtains renewed receipts for all three local review families. All seven future document/review Undo/Redo histories must remain usable. Separate Node IDB/lock fixtures test count-first reads, conflicting records, post-commit refusal, late namespace reservation and late success cleanup. These are not physical browser crash-durability or cross-device fencing tests.

Still required: restoration/relocation of an entire room into wholly empty underlying source storage; explicit endpoint/database relocation when selected; complete packet/outbox transport custody, provider/client/assets reconciliation, authenticated joint activation, public API stabilization, sustainable materialization performance and the full V1 gates. Restoring these two new metadata namespaces does not claim those capabilities.
