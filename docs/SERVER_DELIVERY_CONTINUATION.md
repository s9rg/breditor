# Complete native server continuation after delivery

Delivery legitimately advances the current native server. An old exact recovery
selection must then fail. Merely refreshing its counters or catalogue identity
does not prove preservation of the previously selected complete server state.

This distinct native contract proves A <= B <= C while keeping all three cuts:
A is the real local restore origin, B is an independently selected complete
previous serving archive, and C is the complete current server/registration cut.
The existing generation recovery and older-ancestor physical protocols retain
their original meanings, timing, routes and defaults. No new wire route or
automatic catalogue migration is introduced by this checkpoint.

## Actual native proof

PreparedLogGenerationRecoveryHost::verify_delivery_continuation requires fresh
owner authentication, the complete B archive with a separately pinned identity,
and a genuine existing current proof covering every protected document/comment
registration at C. That proof must belong to this same actual host and owner.

Under the actual room-then-raster transaction locks it rechecks native directory
custody, exact current native/raster/inventory selection and BOTH complete byte
ancestry links. B must retain A; C must retain B. Two independently valid archives
retained somewhere in C do not prove their order. Physical manifests, original
and continuation files, original raster bytes and unreferenced retained uploads
are compared; visible content, author counters and metadata hashes alone cannot
substitute for this native verification.

The resulting VerifiedServerLogGenerationDeliveryContinuation has no public
constructor or deserialization path. It retains the B archive and a weak-host
current credential proof, not the native room, leases or account token. A
byte-identical reopened host requires a fresh runtime proof. check_live freshly
authenticates and rechecks the complete exact state; rotations, ACLs,
registrations, native edits and even raster-only changes stale the old proof.

No file, role, registration, writer, import, receipt, packet, provider mapping or
serving epoch is changed by verification. This is not an outgoing ACK, permission
to mutate, whole-room activation, provider/client closure or a portable grant.

## Reproducible functional coverage

The native workflow covers all forty original language/wire and independent
document/comment-history combinations. Actual offline document/comment suffixes
are admitted through the same native host, independent history and physical log
boundaries remain distinct, old/new rasters survive, and cold ownership plus
future native Undo/Redo are exercised with the old runtime proof still retained.
Separate cases reject genuine native forks, missing predecessor rasters, wrong
pins/authentication/hosts, reversed origin order and stale raster-only proofs.

The real selected-delivery service fixture uses only this public Rust API. Its
first actual target serving snapshot B is retained separately from original A.
Every later capture proves B remains fully preserved by current C. The unchanged
ten-mode seven-author source, fresh-package and executed-production-bundle
workflows require these proof-backed fixture checks, not an optional boolean
substitute for runtime verification. Public fixture reports remain data only.

## Remaining integration

The SDK's old exact generation reader still refuses a changed server selection.
The separate [authenticated delivery control](SERVER_DELIVERY_CONTROL.md) now
composes this primitive with the genuine current native/provider checker. Exact
current inventory/native client adoption and full provider/asset reconciliation
remain required before a resumable delivery coordinator can adopt C. The isolated
prepared-before-client-delivery gate, receipt-backed partial/after journaling,
fresh retry/reapproval, explicit unbound source adoption and real metadata outbox
transport custody still need joint integration. All thirteen V1 gates stay open.
