# Retained native source reconstruction

A failed source save can leave newer document and comment history only in a
complete retained room file. Cold reopening then legitimately restores older
disk data. Ordinary execution resume refuses that mismatch; refusal does not
recover the missing work.

The private original-source reconstruction path builds a new participant backup
from the retained native journals, then uses existing source recovery into absent
databases. It preserves both Undo lanes rather than rebuilding visible trees.

## Read and compare before rebuilding

The inspection holds the actual selected owner and every native client against
editing, publication and selected upload writes. Independently selected read
factories replay the actual current and retained native histories. Every selected
member must precede the retained candidate, and each whole selected upload store
must continue the actual current store. Approval identities must match.

Original dependent packet records, including their complete committed and pending
states, must currently match. Paired relay and policy metadata must also match.
Different packet records require a merge, and conflicting native author branches
refuse. A retained file never silently wins over newer current work. The result
keeps both complete files and grants no source retirement or room activation.

## Native backup construction

The builder admits the original participant file, full committed, pending and
LIVE native records, and every selected version, suggestion and revision record.
Native replay and continuation checks preserve original document and comment
history. The resulting participant contains the LIVE native pair and dependent
records. The complete retained file remains attached with the earlier save
phases, literal origins, original uploads and selected uploads.

Immutable raster bytes resolve from the retained uploads and original exact
asset bindings, or through an explicit host resolver. Missing selected bytes
remain pending. Read grant loss, cancellation, changed native descriptors and
disposed inputs refuse without opening mutable stores.

## Nonoverwriting restoration

Existing participant recovery requires independently supplied current factories
and policies, namespace custody and absent destinations. It creates the genuine
native source and dependent stores; it does not write checkpoint-shaped rows
directly. The original source databases remain unchanged. An existing live writer
still excludes recovery of a second writer.

The regression deliberately fails the real original source save, retains newer
LIVE document and comment history, discards that test-owned failed source and
cold reopens its older disk state. It reconstructs into new databases, verifies
all selected source records and whole original uploads, cold reopens the recovered
stores and compares future document and comment Undo/Redo with a native reference.
Storage and locks are controlled fixtures, not a physical power-loss guarantee.

## Remaining architectural work

This path covers original-source DATA construction and recovery, not a completed
whole-room reconstruction operation. Generation, independent delivery, restored
graph and local-operation families need their own validated recipes. A durable
whole-room intent must retain every complete input before creating targets and
coordinate approved retirement, interrupted retries and a final common handoff.

Compatible histories containing later own offline work and disjoint foreign
operations need a native union contract; a refused incomparable pair is not a
successful merge. Explicit comment adoption, authenticated room activation with
old-writer fencing, sustainable Undo/offline retention, extension parity and all
thirteen V1 release gates remain required.
