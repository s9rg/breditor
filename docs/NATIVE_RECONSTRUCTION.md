# Retained native source reconstruction

A failed source save can leave newer document and comment history only in a
complete retained room file. Cold reopening can then restore older disk data.
Ordinary execution resume refuses that mismatch; refusal does not recover the
missing work.

Private reconstruction paths build new participant backups from retained native
journals for the original and independent-local source families. Existing recovery
restores them into absent databases. Both Undo lanes survive; visible document
trees are never used to reconstruct history.

## Read and compare before rebuilding

The inspection holds the actual selected owner and every native client against
editing, publication and selected upload writes. Independently selected read
factories replay the actual current and retained native histories. Every selected
member must precede the retained candidate, and each whole selected upload store
must continue the actual current store. Approval identities must match.

Original dependent packet records, including their complete committed and pending
states, must currently match. Paired relay and policy metadata must also match.
Different packet records require a merge, and conflicting native author branches
refuse. A retained file never silently wins over newer current work. The result
keeps both complete files and grants no source retirement or room activation.
A later whole-room operation must freshly validate the actual mutable sources,
packets, upload stores and custody; a point-in-time DATA inspection is not a grant.

## Original native backup construction

The original builder admits the original participant file, full committed,
pending and LIVE native records, and every selected version, suggestion and
revision record. Native replay and continuation checks preserve document and
comment history. The new participant contains the LIVE native pair and dependent
records. The complete retained file stays attached with earlier save phases,
literal origins, original uploads and selected uploads.

## Independent local native backup construction

The local builder supports all four original or segmented document/comment
history combinations. It admits the original participant and literal source
origin, recomputes the journal identity, validates the actual intent and every
retained typed cut, and checks exact current/pending references and observed
membership. Digests identify cuts; their lexical order never establishes history.

Retained LIVE must natively continue the original and every current/pending cut,
in both lanes. Immutable version packets must preserve their exact ordered prefix.
Unknown or duplicate cuts, rewritten digests, mismatched native rows and dropped
versions refuse before mutable stores open. Outstanding causal references remain
pending. The resulting independent-local participant contains the exact LIVE
recovery; its full retained room file keeps the complete earlier save phases and
both upload generations. No relay or delivery companion is synthesized.

## Assets and read lifetimes

Immutable raster bytes resolve from retained uploads and original exact asset
bindings, or through an explicit host resolver. Missing selected bytes remain
pending. Read grant loss, changed native descriptors and disposed inputs refuse
without opening mutable stores.

Each DATA builder holds its own genuine input lifetime. Actual input disposal,
its read signal or an explicit asset signal ends a pending builder wait even if
a host native factory or resolver has not settled. Late native results stay
observed and are freed only when unclaimed; an owner already held by a genuine
editor is never freed by the cancelled read. Original factory receivers and
one-shot initialization are preserved. Releasing one builder does not dispose
the reusable input or another builder.

The reconstruction inspector binds the explicit factories to the genuine
selected-owner scope before its first capture, then uses those same bounded
wrappers during native comparison. All seven source families are covered, with
original and segmented factory paths. Aborting an inspection releases its read
barriers so ordinary editing can resume; closing the actual owner does not wait
for these stalled read factories. Late native results are still observed.

This scope belongs to reconstruction inspection. Other legacy public read and
capture APIs keep their existing callback contracts. Actual source and storage
cleanup still runs normally and can report its own failures. Cancellation neither
acknowledges a source write nor retires a source on behalf of the host.

## Nonoverwriting restoration

Existing participant recovery requires independently supplied current factories
and policies, namespace custody and absent destinations. It creates genuine
native sources and dependent stores rather than writing checkpoint-shaped rows.
Original databases remain unchanged. An existing live writer still excludes
recovery of a second writer.

Original and independent-local regressions fail actual source saves, retain newer
LIVE document/comment history and cold reopen older disk data. The local case
first leaves a complete pending attempt, then retains a newer unsaved suffix;
cold reopening may legitimately adopt that pending attempt without recovering
the later suffix. New destinations restore exact retained LIVE, cold reopen and
compare future document/comment Undo/Redo with a native reference. Controlled
storage and locks do not establish physical power-loss durability.

## Remaining architectural work

Two family-specific DATA/recovery paths do not complete whole-room reconstruction.
The other five source families need their own validated recipes. A durable
whole-room intent must retain every complete input before creating targets and
coordinate approved retirement, interrupted retries and a final common handoff.

Compatible histories containing later own offline work and disjoint foreign
operations need a native union contract; a refused incomparable pair is not a
successful merge. Explicit comment adoption, authenticated room activation with
old-writer fencing, sustainable Undo/offline retention, extension parity and all
thirteen V1 release gates remain required.
