# Retained native source reconstruction

A failed source save can leave newer document and comment history only in a
complete retained room file. Cold reopening can then restore older disk data.
Ordinary execution resume refuses that mismatch; refusal does not recover the
missing work.

Private reconstruction paths build new participant backups from retained native
journals for the original, generation, independent-local, independent-delivery
and restored-graph source families. Existing recovery restores them into absent databases. Both Undo lanes
survive; visible document trees are never used to reconstruct history.

## Read and compare before rebuilding

The inspection holds the actual selected owner and every native client against
editing, publication and selected upload writes. Independently selected read
factories replay the actual current and retained native histories. Every selected
member must precede the retained candidate, and each whole selected upload store
must continue the actual current store. Approval identities must match.

Original dependent packet records, including their complete committed and pending
states, must currently match. Paired relay and policy metadata must also match.
Different packet records require a merge, and conflicting native author branches
refuse. A retained file never silently wins over newer current work. The result
keeps both complete files and grants no source retirement or room activation.
A later whole-room operation must freshly validate the actual mutable sources,
packets, upload stores and custody; a point-in-time DATA inspection is not a grant.

## Original native backup construction

The original builder admits the original participant file, full committed,
pending and LIVE native records, and every selected version, suggestion and
revision record. Native replay and continuation checks preserve document and
comment history. The new participant contains the LIVE native pair and dependent
records. The complete retained file stays attached with earlier save phases,
literal origins, original uploads and selected uploads.

## Generation native backup construction

The generation path preserves each explicitly selected local, relay or retained
source kind. It admits both protected origin files and the exact recovery and
operation plans. Committed heads must match their complete immutable file list
and decoded native head. An attempted cut, when present, must exactly encode its
captured document, comments, versions and companion. Pending and LIVE captures
keep their closed shapes; projection cannot discard unknown companion fields.

Native replay must continue every earlier state, including original roots and
sealed generations, in both lanes. Immutable version order and relay progress
must continue too. Facade revision strings remain captured observations, not
ancestry counters or writer grants. Shared asset framing preserves the existing
generation format and opaque native strings; a pinned pre-refactor file protects
its byte compatibility. The inspector applies the same retained-packet
conservation rules as delivery recovery without changing either source protocol.

## Independent local native backup construction

The local builder supports all four original or segmented document/comment
history combinations. It admits the original participant and literal source
origin, recomputes the journal identity, validates the actual intent and every
retained typed cut, and checks exact current/pending references and observed
membership. Digests identify cuts; their lexical order never establishes history.

Retained LIVE must natively continue the original and every current/pending cut,
in both lanes. Immutable version packets must preserve their exact ordered prefix.
Unknown or duplicate cuts, rewritten digests, mismatched native rows and dropped
versions refuse before mutable stores open. Outstanding causal references remain
pending. The admitted native components must round-trip the complete LIVE wrapper
without discarding unknown fields. The resulting independent-local participant contains the exact LIVE
recovery; its full retained room file keeps the complete earlier save phases and
both upload generations. No relay or delivery companion is synthesized.

## Independent delivery native backup construction

The delivery builder re-admits the genuine parent recovery plan and its complete
source and upload phases. It recomputes the operation identity from the declared
namespaces, checks the literal origin and every current/pending cut, and requires
LIVE to continue both native lanes, relay progress and ordered immutable versions.
The admitted component records must round-trip the complete LIVE wrapper exactly;
a projection cannot relabel a mismatched identity, binding or unknown field.
The resulting participant contains the exact LIVE recovery, including selected
suggestion queues, revision outboxes, version packets and relay receipts. Pending
decisions remain pending; reconstruction does not finalize or publish them.

Before construction, the inspector compares the current and retained delivery
records under the common native and upload read. Additional admitted packet rows
are allowed only when every earlier complete row remains unchanged. Changing a
queued decision or retry flag, dropping a packet, changing an existing catalog
or selecting different retained bindings requires explicit reconciliation.
Historical current/pending cuts can legitimately contain earlier packet states;
they are replayed individually and retained in the complete input file, not
silently restored over LIVE. A DATA recipe alone does not compare a mutable source
and cannot grant permission to replace one.

## Restored graph native construction

The graph builder keeps the existing graph family and appends one state to its
exact literal input. It independently admits the original participant, complete
parent plan, declared input digest, operation identity and completed bootstrap
journal. Current, pending, observed and retained cuts must agree, including their
complete native files and recomputed asset references.

Original, input, current, pending and LIVE histories must continue both native
lanes, ordered immutable versions and relay progress. The appended state keeps
the actual current, pending and observed save phases; newer LIVE is not labelled
as a successful source save. The normal graph reader then re-admits the complete
ancestry and native state before a recipe is returned. The predecessor can still
be reconstructed byte-for-byte, and shared append framing is pinned against a
genuine pre-refactor graph file.

Inspection compares complete current and retained packet rows under the same
all-member native and upload preflight as delivery recovery. Additional rows
cannot replace existing decision, retry or publication intents. Decisions remain
queued, literal inputs and original databases remain intact, and new source and
upload namespaces must be absent. Both original and segmented document/comment
lanes preserve future Undo and Redo after recovery and cold reopening.

## Assets and read lifetimes

Immutable raster bytes resolve from retained uploads and original exact asset
bindings, or through an explicit host resolver. Missing selected bytes remain
pending. Read grant loss, changed native descriptors and disposed inputs refuse
without opening mutable stores.

Each DATA builder holds its own genuine input lifetime. Actual input disposal,
its read signal or an explicit asset signal ends a pending builder wait even if
a host native factory or resolver has not settled. Late native results stay
observed and are freed only when unclaimed; an owner already held by a genuine
editor is never freed by the cancelled read. Original factory receivers and
one-shot initialization are preserved. Releasing one builder does not dispose
the reusable input or another builder.

The reconstruction inspector binds the explicit factories to the genuine
selected-owner scope before its first capture, then uses those same bounded
wrappers during native comparison. All seven source families are covered, with
original and segmented factory paths. Aborting an inspection releases its read
barriers so ordinary editing can resume; closing the actual owner does not wait
for these stalled read factories. Late native results are still observed.

Read and asset cancellation signals cover the complete inspection, including
its first capture. Raster admission stops waiting when its real signal is
cancelled, even if image decoding has not returned. Temporary object URLs are
revoked, and late decoder success or failure stays observed. Disposing a DATA
input also cancels its pending raster admission. The actual room can close
without waiting for that decoder, and a cancelled read leaves editing barriers
released. Calls with invalid room custody leave no signal listeners behind.

This changes cancellation, not image admission: ordinary decoding, exact pixel
bytes and content identities, MIME and dimension checks, resource limits and
archive formats retain their meanings. A read without cancellation still waits
for its decoder; no new deadline substitutes for a valid result.

This scope belongs to reconstruction inspection. Other legacy public read and
capture APIs keep their existing host-factory callback contracts. Public raster
and whole-archive reads now honor their existing cancellation signals while
decoding, before opening any restore destination. Actual source and storage
cleanup still runs normally and can report its own failures. Cancellation neither
acknowledges a source write nor retires a source on behalf of the host.

## Nonoverwriting restoration

Existing participant recovery requires independently supplied current factories
and policies, namespace custody and absent destinations. It creates genuine
native sources and dependent stores rather than writing checkpoint-shaped rows.
Original databases remain unchanged. An existing live writer still excludes
recovery of a second writer.

Original, generation, independent-local, independent-delivery and restored-graph
regressions fail actual
source saves, retain newer LIVE document/comment history and cold reopen older
disk data. The independent cases first leave a complete pending attempt, then
retain a newer unsaved suffix;
cold reopening may legitimately adopt that pending attempt without recovering
the later suffix. New destinations restore exact retained LIVE, cold reopen and
compare future document/comment Undo/Redo with a native reference. Controlled
storage and locks do not establish physical power-loss durability.

## Remaining architectural work

Five family-specific DATA/recovery paths do not complete whole-room reconstruction.
The two local-operation input families still need validated recipes. A durable
whole-room intent must retain every complete input before creating targets and
coordinate approved retirement, interrupted retries and a final common handoff.

Compatible histories containing later own offline work and disjoint foreign
operations need a native union contract; a refused incomparable pair is not a
successful merge. Explicit comment adoption, authenticated room activation with
old-writer fencing, sustainable Undo/offline retention, extension parity and all
thirteen V1 release gates remain required.
