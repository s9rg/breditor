# Durable native generation activation and cold restart

This opt-in native-service path retains a complete target checkpoint before a
target-bound epoch can be committed. A cold restart uses a new authenticated
decision and fresh epoch, never a recreated saved lease. Existing warm-only APIs,
source-handover meanings, native archives, default routers and 104-byte deployment
frames are unchanged. Complete browser/provider/packet reconciliation and all
thirteen V1 gates remain open.

## First activation: retain the actual whole target cut

After durable source handover and genuine operational recovery, authenticate the
target owner using independently configured current account credentials. Capture
its complete current native/raster state and verify all current protected stream
registrations. Revoked/observer streams remain required; missing credentials
cannot produce a usable verification proof.

Call prepare_durable_native_activation with that same-host proof, actual sealed
source owner and independently configured NativeGenerationActivationPrepareOptions.
The options select an absent private directory and genuine deployment authority;
incoming archive metadata selects neither. The prior epoch must be exactly the
source's sealed nonce. Capture checks actual original/operational/native/raster
custody and the entire independently selected current state before creating files.

The existing complete joined archive is streamed to target.backup, synced and
read back. Canonical activation.json is then synced. The closed directory contains
only these files and its original .owner marker. Its identity commits to the
complete source intent, whole current target, all registration identity data,
actual operational owner digest, prior epoch, random salt, original checkpoint
directory/file witnesses and byte length. The planned nonce uses a separate
durable-native-activation domain; it does not reuse warm-only choices.

Retain PreparedNativeGenerationActivationIdentity independently and durably before
calling activate_durable_native_service. Preparation creates no epoch, routes,
client acknowledgements, role changes or accepted native events. Target edits
after capture can stale this preparation; final activation must check equality
again. Existing/partial roots are preserved, never overwritten or silently repaired.

## Commit using the actual source, target and authority

Activation authenticates again, requires the genuine same-host registration proof
and matches the independently selected checkpoint. Its worker holds the one-time
shared attachment gate, actual exclusive epoch permit, native room and raster
owners. It checks the exact prior nonce, retained original source seal, complete
checkpoint files, same operational owner and whole current target cut. A counter
projection, portable backup, copied directory or serialized success flag is not
authority. Wrong choices or changed native/physical/raster state append nothing.

Actual original, source and checkpoint owners enter shared serving custody before
an append can become durable. The shared retired state is independent of whether
a lease returned. Only complete checked publication clears retirement. A failure
after a synced append cannot fall back to an unfenced host, refresh an old clone,
discard original custody or roll back the epoch. Routers, earlier handles and
detached workers retain the same actual owners until they all drop.

## Cold restart with a fresh current cut

Close the old service and retain its complete files and independent choices. Open
the actual source and latest checkpoint using their separately retained identities.
Re-admit the original operational room at the SAME physical operational directory
and intent owner. Configure fresh host account authentication and verify every
current protected registration again. Old source tokens and ephemeral writer
leases are not resurrected from the archive.

Call prepare_durable_native_restart with the actual prior committed checkpoint.
Its planned epoch must be the exact current authority selection. The new genuine
current archive must contain ALL prior checkpoint native history and rasters,
including unreferenced uploads, not just extend the older original source. The
actual operational owner digest must match. Legitimate later events and physical
generations are allowed; forks, rollback or loss of checkpoint data refuse before
creating a new directory. The new checkpoint retains the whole new current cut
and references the prior choice by digest; older files are not rewritten/pruned.

Persist the new independent identity, then activate it with fresh current proof.
This appends the next source/target-bound epoch. It never reissues the previous
lease or treats an earlier READ/COMMITTED result as permission to serve.

Cold status is DATA from complete actual epoch lineage:

- Prepared: the exact previous epoch remains current; target equality still needs checking.
- Committed: this exact planned nonce is retained, possibly below later epochs.
- Superseded: an unrelated decision replaced the prior epoch without this nonce.

An unrelated claim at the same ordinal is not this activation. Incomplete or
divergent ledgers and changed checkpoint/source custody refuse without repair.
Warm descriptor reads serialize their shared file cursors; observed uncertainty
permanently retires that checkpoint even if old names later reappear.

## Interruption and data retention

Native and file work runs on blocking workers. Cancelling an awaiting future
does not cancel a worker that already owns source/checkpoint/native exclusion.
Preserve all files and independent choices: it may finish a durable transition
after the caller stops waiting. A pre-commit restart can reuse its exact complete
prepared cut if still current; a post-commit restart needs a fresh checkpoint and
new epoch. Tests terminate real child processes before commit, after sync but
before any lease returns, and after publication, then freshly authenticate and
continue from original files. These are process tests, not hardware power-loss
qualification or multi-machine consensus.

The backend assumes private trusted namespaces, cooperating Unix file locks and
fsync. Complete checkpoints cost space proportional to retained native/raster
history; this path does not compact or prune. Existing byte and epoch ceilings
remain. A valid later journal tail is replayed normally. If ALL files and outside
witnesses roll back together, later missing accepted work cannot be inferred.
Provider/client reconciliation is still needed to establish every outstanding
client/offline/packet boundary; this native path never acknowledges those queues.

## Coverage and explicit remaining boundaries

Native workflows cover forty grammar/profile, transport and independent document/
review history combinations. Public-only consumers stop actual HTTP/WebSocket
services, cold-open the original files, configure fresh accounts and resume both
offline lanes in ten modes. Exact duplicate receipts, future native Undo/Redo and
original raster bytes survive. Negative laws retain the original source while
removing a later checkpoint event or unreferenced raster and require refusal.
Actual process exits, cancelled workers, wrong operational copies, stale physical
cuts, namespace retirement and shared readers are separate functional checks.
Both candidate profiles require native and public cold-restart stages.

This is a durable-first opt-in path, not automatic migration of an already running
warm-only activation. Cross-directory/disaster relocation, warm-only adoption,
complete provider/client/historical-packet settlement, explicit unbound-comment
adoption and coordinated whole-room/browser-owner activation remain required.
No raw native-parts escape or legacy unfenced router is an acceptable shortcut.
Normal Wasm/browser packages are unchanged here; old installed npm/bundle results
are historical evidence, not fresh executions in this native checkpoint. No
historical WebKit or parallel TCP-shutdown fault is declared repaired.
