# Source-owned complete metadata asset availability

The private selected metadata owner exposes `captureAssetAvailability(host)`.
One actual parent capture/quiescence covers source saves, both receipt/metadata
journals, exact before/stored/current reference reconstruction, both complete
upload-archive roles, and the authenticated provider operation. The original
`captureReferences()`, room formats and default protocols remain unchanged.

The returned separately named bundle contains the literal complete reference
bundle and immutable availability data. Every selected participant contributes
both its original and selected upload archive, including unreferenced uploads.
Original adoption limits, exact archive hashes, payload admission and immutable
content metadata are checked. A caller cannot supply a reduced upload list.

A genuine generation recovery controller must match the archive's source tuple.
After server-side edits or metadata publication it can be stale. A genuine
native delivery-continuation controller can instead prove the exact archived
previous server point to its freshly authenticated current server. A room name,
matching rendered text, copied controller selection or new common descendant
cannot replace that native predecessor proof. The actual controller class ports
are used; public method shadows never supply a port.

Complete Ready dependencies are submitted with all upload content IDs to the
original native server/client asset-requirement API. Its response includes the
selected server's own requirements. Available local/provider metadata must
agree. Missing mappings or bytes yield Pending. An incomplete native/packet
reference cut yields Pending with no provider report and no partial dependency
union presented as complete. All seven source document/comment stamps and the
actual owner lifetime remain checked throughout asynchronous work.

The actual metadata operation is registered before callbacks. Close cancels
finite provider/account work, retains later committed source/metadata facts,
and prevents a late account result from starting HTTP. Original packets,
receipts, Undo/Redo and offline edits retain their original contracts.

This is a current byte-availability observation. It does not materialize newly
resolved remote bytes into an offline recovery archive, settle accepted client
heads, acknowledge upload queues, or grant a serving/activation role. Those
steps remain required for complete whole-room recovery and V1 readiness.
