# Current Native, packet-source and provider reconciliation

This contract supplements the original reconciliation read. Original cache,
queue and provider meanings do not change. Its [qualification](qualification/2026-11-01-current-server-packet-reconciliation.json)
passes eight source and eight independently installed cases with strict public
types. Both candidate profiles require these checks; the complete profiles and
all thirteen V1 gates remain open.

`SelectedLocalMetadataDelivery.captureServerPacketReconciliation({host, inventory})`
uses the same genuine selected delivery host and inventory as the original
current reconciliation method. The input has no server archive, asset transport
or caller-supplied requirement list. This is a current reference/provider read;
it does not capture a byte backup.

The immutable `ServerPacketReconciliationRead` DATA contains:

- `original`: the complete literal earlier current reconciliation, including
  Pending cache and diagnostic meanings.
- `sources`: a separately named current reference scope covering held Native
  histories, exact local retained packets, source-version snapshots and the
  complete actual server Native dependency inventory.
- `currentProvider`: the full reference/upload requirements, all original and
  selected upload-role pins, and the actual current provider read, or `null`
  while sources remain unknown.
- `pending`: every remaining Native, registration, review, real metadata-operation,
  source and provider blocker.

No full server packet archive is constructed or claimed. Every original local
packet is discovered at its held metadata points, including the separately
admitted stored local cut. Distinct original strings retain their encoded-byte
identity. Genuine current Native cores decode references; missing sources retain
all actual attempt details. Constructor-bound readonly factories admit each saved
Native family and its literal version snapshots. Historical Native references
remain included even when a separate old metadata lane is Pending.

The actual server contributes its complete physical Native inventory and packet
identities. A matching retained local packet, a decoded source-version snapshot
or an exact complete server source can establish additional immutable source
knowledge. Unknown identities and unreconciled clients stay Pending. An uncached
version can therefore remain Pending in `original` while the full current
reference set is known. This path requests neither first-server packet bodies,
version-history packet downloads nor raster downloads; those belong to the
separate complete recovery capture when byte retention is required.

Current server availability is separate from local retained bytes. The provider
is queried for every derived asset/generation pair and every whole-upload ID.
Its returned asset information must agree with admitted local upload information;
all fourteen roles remain present in the seven-family case. Missing mappings,
reference bytes or upload bytes stay Pending. A second provider read must match.
No partial reference prefix is sent when source knowledge remains Pending.

The same genuine metadata task holds actual current Native document/review
stamps, constructor-bound factories, source/host checks and the final journal
CAS. The selected Native response and original current control must agree.
Every source is admitted; an earlier successful packet witness does not skip
another family. The data result has no writer, acknowledgement or activation
method and never changes cache, queue, role or Native editing state.

The qualified workflow uses real managed image acknowledgements and two
original protocol passes over all seven families. It refreshes version catalogs
without loading every historical packet, then rejects any packet/raster download
during the new current read. It compares old Pending with the new result and
checks unchanged Native state, queue/cache fields and older metadata bytes,
followed by original document/review Undo/Redo. Saved Native DATA checks separately
omit a real server-only packet string while retaining its required image through
complete Native server references. DATA-only laws retain actual-operation
blockers and provider loss.

Independent generation integration, authenticated whole-room activation and
complete release profiles remain separate requirements. All thirteen V1/parity
gates remain open.
