# Selected generation native reconciliation

Generation recovery now checks the actual retained clients against every selected
accepted author while both origin and selected upload stores remain held. The
standalone origin/current control remains separate from physical A/B/C recovery.
The read exposes missing work and compatible offline suffixes without converting
either into an acknowledgement or permission to activate the room.

## Genuine source and native custody

The private selected owner supplies its actual retained root and seven concrete
native/source families. Fresh factories cannot supply native clients, invent a
server identity or replace the current catalog. Generation source admission binds
the genuine host's origin, current server and participant inventory separately.
It never creates ancestor or localOrigin aliases.

The generation entry point reserves the owner before synchronously detaching
read choices. Both selected uploads and complete origin readers remain held before
the first fresh grant or operator request. The shared private byte projection
does not weaken the original physical host brand, source comparison or report.
Neither new report nor private reader is a default package-root export.

## Accepted prefixes and outstanding native work

Native comparison checks every selected client against every registered and
server document author. Each bound comment lane is also checked against every
accepted comment author. Counters alone are insufficient: the original native
prefix digests must agree at the selected accepted cut. A conflicting prefix
refuses before provider I/O, including when another author is merely behind.

The separate selected-generation report contains aligned accepted-author vectors
and explicit local-ahead or server-ahead requirements. Compatible local suffixes
are preserved work, not accepted operations. A covered accepted prefix therefore
does not by itself produce a checked generation reconciliation result. Missing
registrations, omitted retained participants and unbound local comment lanes
remain Pending in the native result. Requirement output refuses beyond 100,000
rows rather than truncating unresolved work.

The result families are breditor/selected-generation-provider-read and
breditor/selected-generation-reconciliation-read, both revision one. Checked
means selected registered heads agree and required bytes are available. It does
not certify unknown-author discovery, complete retained outbox settlement or
whole-room activation. Existing physical result families retain their meanings.

## Reserved accepted native imports

The existing private native recovery scope now has the same generation read.
An authorized enclosing operation can obtain genuine accepted document frames
and comment pages from the selected generation host, then admit them to actual
held client cores using their original native contracts. Historical comment
source roles and receipts remain server-verified; reader roles do not change
recipient permission. Unbound local lanes stay unbound.

Native imports preserve existing Undo/Redo and offline work. They neither settle
source or packet journals nor acknowledge an outstanding own suffix. The scope
excludes ordinary aliases during admission, performs fresh per-import authority
checks and drains unfinished reads before releasing exclusion. A failed attempt
can retain already admitted native changes; it never fabricates a rollback.

These are private functional operations. The separate
[generation executor](GENERATION_NATIVE_EXECUTION.md) retains complete inputs and
per-client/resume journals before native admission. The read and scope alone do
not provide that execution or whole-room activation.

## Lifetime and provider availability

Provider reads resolve the union of native references and all whole-upload IDs,
including unreferenced bytes. A local uploaded receipt cannot replace missing
provider bytes. Native histories, complete current and pending source records,
root/catalog data and both upload sets are checked after provider I/O.

Actual selected-store cleanup acknowledgements precede return. Fresh final
permission, cancellation and the same root-owned native witness are checked
after that cleanup; edits or comment changes during release refuse the stale
result. No mutable core, credential or writer lease escapes in a report.
