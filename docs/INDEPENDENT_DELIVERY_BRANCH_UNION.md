# Complete independent delivery source union

Breditor can prepare one compatible replacement source containing native document and comment histories, suggestion drafts and decisions, revision outboxes, version caches, local immutable versions and relay progress. Preparation runs on private read-only native owners. A late store or receipt conflict returns no partial replacement and leaves live sources and their adapters untouched.

The public prepareSharedIndependentDeliveryBranchUnion function accepts two complete serialized recoveries, explicit matching read-only factories, independently authenticated original comment role/prefix windows and a current host check. It returns frozen DATA with both exact original strings and a replacement recovery in the existing independent-delivery format. A separately authorized absent-only restore can consume that recovery; preparation itself opens no database, acquires no writer lease, contacts no relay and activates no room.

## Original histories and dependent stores

Both complete inputs first pass their existing closed record codecs and separate native replays. A third native owner stages the [atomic document and comment union](NATIVE_BRANCH_UNION.md). It must natively cover both originals while preserving the selected current local Undo/Redo histories and immutable generation files. Unknown source-local author suffixes, causal forks and incomparable sealed branches retain the existing refusal semantics.

Suggestions, revisions and catalog packets are then reconciled together using the existing native-admitted store mergers. Current-only and incoming-only rows survive. Duplicate immutable identities with different bytes, incompatible terminal receipts and opposite outstanding retry choices refuse; timestamps never choose a winner. A known consistent terminal outcome can stop its retry in the replacement, while both original intent records remain in the returned inputs. Saved receipts establish continuity data, not independently authenticated server authority or a new decision.

Local immutable version packets are a separate cache, not the server catalog. Exact duplicate packets are retained once; selected-current order is kept and unseen incoming packets append in their incoming order. Both complete original lists remain available in the retained input strings. Different bytes at one immutable ID and a union exceeding the existing 32-packet limit refuse without eviction. Ordinary strict-prefix reconstruction remains unchanged.

## Independent relay progress

Document acceptance, document receipt, comment acceptance, comment receipt and read cursor are separate monotonic registers. Preparation keeps only values already present in an input, proves their native prefixes and requires the joined result to continue both original progress records. A crossed cursor can advance independently of an accepted author prefix. Conflicting equal-position receipts, inconsistent server sequence order, prefix forks and receipt rollback refuse. Neither taking a numerical maximum nor possessing a native digest authenticates a server claim.

## Native ownership and interruptions

No live adapter cache is replaced behind its owner's back. Preparation restores private copies, snapshots factories and historical grants before awaiting native work, and holds actual native exclusion during staging. Every result is re-admitted through the original complete recovery codec and delivery companion before publication. Current host checks cover the work; aborting an unsettled factory frees an eventual unclaimed native owner without exposing it.

The preparation contains both exact serialized inputs in their existing closed formats, rather than merely their digests or current ASTs. Hosts must persist those inputs before separately authorized replacement. The existing paired source transaction writes both native lanes, immutable files, local versions, relay state and all three selected retained records together. An aborted transaction can retry into an absent destination; commit-before-ack requires inspecting and reopening the committed destination instead of overwriting it.

## Remaining room integration

This source union does not itself journal preparation, merge whole upload stores, resolve conflicting user intents, affiliate an unbound comment lane, reconcile every operational source family or authenticate cross-device activation. The whole-room workflow must preserve its complete original archives and explicit asset decisions, retire old owners under held custody, admit interrupted targets and join the authenticated serving fence. A saved preparation is DATA and must not become a credential or reusable role grant. All thirteen V1 gates remain open.
