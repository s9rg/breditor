# Content Security Policy and Trusted Types

Status: tested guidance for the unpublished `0.3.0-alpha.22` editor packages
(`@breditor/editor`, `@breditor/collaboration`, `@breditor/experimental-rich-content`,
`@breditor/interchange`, `@breditor/browser`). It covers the editor and its Wasm runtimes.
It does not cover the crash-restart watchdog, a network relay origin you operate, or
pages your application adds around the editor.

## The strict policy

This is the strictest policy the editor runs under. The automated gate in
[`tests/csp`](../tests/csp) serves exactly this header, generated by
[`tests/csp/policy.mjs`](../tests/csp/policy.mjs):

```http
Content-Security-Policy: default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'nonce-{NONCE}'; img-src 'self' blob:; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; require-trusted-types-for 'script'; trusted-types breditor-static-html
```

`{NONCE}` is a fresh random value for every HTML response. Publish the same value once in
the page head, before the editor loads:

```html
<meta property="csp-nonce" nonce="{NONCE}">
```

This is the convention Vite's `html.cspNonce` emits, so a Vite host can set that option
instead of writing the tag. The editor reads the nonce from this tag, so no mount option is
needed.

| Directive | Why the editor needs it |
| --- | --- |
| `default-src 'none'` | Everything not listed is refused. The editor uses no frames, workers, fonts, media, manifests or plugins. |
| `script-src 'self' 'wasm-unsafe-eval'` | Bundled module scripts. The Rust core and the shared runtime compile WebAssembly. `'wasm-unsafe-eval'` allows only Wasm compilation, not `eval` or `new Function`. The packages and the `wasm-bindgen` glue use neither, and they create no inline scripts. |
| `style-src 'self' 'nonce-…'` | Your bundled stylesheets, plus the editor's own `<style>` elements. Every one of them copies the published nonce before it gets its CSS text. |
| `img-src 'self' blob:` | Inserted and restored images are shown through `URL.createObjectURL` from the local asset store. Raster checks decode through the same kind of URL. |
| `connect-src 'self'` | `fetch` of the `.wasm` files (`WebAssembly.instantiateStreaming`). |
| `require-trusted-types-for 'script'` | The editor never assigns a string to an HTML or script sink. |
| `trusted-types breditor-static-html` | Allows the one policy the packages create, for static render output (see below). If you never insert static render output in the browser, use `trusted-types 'none'`. |
| `base-uri`, `form-action`, `frame-ancestors` | Hardening with no editor requirement. |

The policy does not need `'unsafe-inline'`, `'unsafe-eval'`, `'unsafe-hashes'`, `data:`, or a
`'strict-dynamic'` loader. If your server cannot send a nonce, see
[Hosts without a nonce](#hosts-without-a-nonce).

## Trusted Types

The packages contain no `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`,
`createContextualFragment`, `srcdoc`, `setHTMLUnsafe`, `DOMParser`, `eval`, `new Function` or
string timers. Each path that handles HTML avoids a sink:

- **Clipboard HTML paste** (`@breditor/interchange`) parses with `parse5` into a plain
  JavaScript tree under resource budgets. It never builds a live or inert DOM, so pasted
  `<script>`, event handlers and `<img onerror>` stay inert data. They are dropped, never run.
- **Copy** writes strings to `DataTransfer`. It is not a DOM sink.
- **HTML source view** (`mountSourceView`) shows and edits source only as `<textarea>` text,
  and imports through the same `parse5` adapter.
- **Live rendering, chrome, panels and collaboration overlays** use `createElement`,
  `textContent`, attributes and CSSOM only.
- **Static render** (`renderStaticDocument*`) returns an escaped HTML string. Inserting that
  string is the only HTML sink. It goes through one named policy:

```ts
import {renderStaticDocumentTrustedContents,staticTrustedTypesPolicyName} from "@breditor/editor";
// staticTrustedTypesPolicyName === "breditor-static-html"
target.innerHTML = renderStaticDocumentTrustedContents(editor.view().documentJson) as string;
```

`renderStaticDocumentTrustedContents` returns `TrustedHTML` when the browser implements Trusted
Types, and the same string elsewhere, including during server rendering. The policy object is
private to the module, and only renderer output reaches it. Allowlisting the name therefore
does not let other strings through. `BreditorStaticDocument` (React) uses the same function. If the host policy
leaves out the name, creating the policy throws a `StaticDocumentError` with code
`trusted-types-policy`.

## Styles

All editor chrome stylesheets are created in one place:
`createRichStyleElement` in `@breditor/experimental-rich-content`. It sets `nonce` before
the CSS text. The order of precedence is:

1. An explicit per-feature `nonce` option, which `mountCodeHighlighting` and
   `mountEditingAids` already accept.
2. The `<meta property="csp-nonce">` value.
3. No nonce. This is the earlier behavior, for policies that allow inline style elements.

Positioning and sizing of overlays, handles, the placeholder, table columns and block
layout use CSSOM (`element.style.x = …`). CSP does not govern CSSOM.

### Inline `style` attributes: the one documented relaxation

A small set of policy-derived formats keep their exact canonical `style="…"` attribute. That
string is part of the DOM, copy and test contract (for example `style="color:#336699"`):

| Feature | Attribute |
| --- | --- |
| Text color, background color | `color:#rrggbb`, `background-color:#rrggbb` (RGB24 only) |
| Text size | `font-size:{8..96}px` |
| Page break | `break-after:page;page-break-after:always` |
| Static render output | the same values, plus table column widths and block layout codes |

Under the strict policy, the browser blocks these attributes. The text and format stay in the
document, but the style is not applied, and each one reports a `style-src-attr` violation.
Chromium and WebKit keep the attribute string in the DOM. Firefox leaves the attribute empty. A host that uses these features, or pastes content that maps to
them, adds exactly one directive:

```http
style-src-attr 'unsafe-inline'
```

This allows style **attributes** only. It does not allow `<style>` elements or scripts, and it
does not allow another Trusted Types policy. The editor never copies a pasted `style` value.
Each attribute is regenerated from a validated integer or RGB24 value. The gate tests both
sides: under the strict policy, text color yields only `style-src-attr` violations, and with
the relaxation it applies with none.

## Per-feature requirements

| Feature | Additional sources |
| --- | --- |
| Local editing, typing history, undo/redo, toolbar, panels, menus, source view | none |
| Clipboard paste and copy (plain, rich, HTML, Markdown) | none |
| Images from files or the local asset store | none (`blob:` is in the strict policy) |
| Images your `resolveAsset` returns as `https:` or `data:` URLs | that origin, or `data:`, in `img-src` |
| `prepareRichRasterUrl` remote image intake | the image origins in `connect-src` (your loader fetches them) |
| Shared editing over a network relay | the relay endpoint in `connect-src`, for example `wss://relay.example` |
| Shared editing between replicas in one page | none |
| Text color, background color, text size, page break | `style-src-attr 'unsafe-inline'` |
| Static render inserted in the browser | `trusted-types breditor-static-html`. Add `style-src-attr 'unsafe-inline'` when the document has colors, sizes, column widths or block layout |
| Print preview | none (its stylesheets carry the nonce) |
| A development server (Vite dev, HMR) | not covered. Development servers inject inline scripts and websockets. Test the production build. |

## Hosts without a nonce

Static hosting cannot mint a nonce for each response. The editor's stylesheets are built at
run time, and some include per-mount values (code-highlight names, the fullscreen marker,
print layout), so a fixed hash list cannot cover them. Such hosts have two options:

- Use `style-src 'self' 'unsafe-inline'`. Everything else in the strict policy is unchanged:
  scripts, Wasm, Trusted Types and images stay strict.
- Use an edge function or server that adds the nonce to the HTML response.

Constructable stylesheets (`adoptedStyleSheets`) would avoid a nonce. They are not used yet,
because they change the cascade and shadow-root placement of the existing `<style>`
elements.

## What the gate proves

`npm run test:csp` builds the packages and the fixture pages, then runs
[`tests/csp/strict-csp.spec.ts`](../tests/csp/strict-csp.spec.ts) in Chromium, Firefox and
WebKit. Before that, build the Rust runtimes with `node scripts/build-rich-runtime.mjs` and
`node scripts/build-collaboration-runtime.mjs`. The fixture is a Vite production build of
the package roots, with no inline code. It is served with the exact header above and a
fresh nonce for every response. Each test records `securitypolicyviolation` events, console
errors and page errors from before the first script runs. The tests are:

- **Control.** A stylesheet without a nonce is refused. Where Trusted Types exist, a raw
  `innerHTML` string throws. The recorded violations match exactly, which shows that the
  zero-violation results below are meaningful.
- **Local editing.** Typing, HTML paste (including `<script>` and `onerror` payloads),
  keyboard undo, PNG image insertion shown through `blob:`, and static render insertion
  through `breditor-static-html` raise zero violations. Every `<style>` element carries the
  nonce and applies.
- **Shared editing.** Two shared replicas joined by an in-page frame relay type, converge and
  undo with zero violations.
- **Style attributes.** Under the strict policy, text color yields only `style-src-attr`
  violations. Under the documented relaxation, it applies with zero violations.

Browser coverage: the gate requires Chromium to enforce Trusted Types. With the locked
Playwright 1.62.1 browsers, the control test also found Trusted Types enforced in Firefox
and WebKit, so all 15 cases ran with both CSP and Trusted Types. An older engine without
Trusted Types ignores those two directives, and the gate then checks only the CSP part. The
control test annotates which case applied. This is evidence from the bundled engines, not
native Safari or released Firefox channels.

Not covered: a network WebSocket relay (it needs the native relay build; its only extra
requirement is `connect-src`), the React entry, development servers, browser extensions that
inject content, and report-only deployment.
