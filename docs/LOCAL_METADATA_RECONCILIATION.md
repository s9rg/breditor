## Capture contract

`SelectedLocalMetadataDelivery.captureReconciliation({host, inventory})` requires
the actual current delivery-continuation controller and its genuine selected
inventory reader. Original prototype methods admit the reader and its lifetime;
public method shadows, copied fields and matching inventory JSON do not suffice.
Unknown input fields refuse. Busy exclusion and the actual capture promise are
registered before input reflection, authority callbacks or asynchronous work.

The real parent quiesces all delivery contexts. Capture saves and admits the
whole native/source cut, both journals, original metadata packets and all origin
and selected upload archives. All seven native stamps stay fixed through the
read. The complete dependency/provider read and original current-inventory read
must name the same record cut, approval, controller and fourteen upload pins.
The complete provider requirement set is checked again before return.

Every document author and previously bound comment author keeps the original
native prefix proof. For the three separately bound local lanes, the operation
uses the genuine owner's already admitted choice, current saved relay progress,
actual core and exact native receipt. It rechecks every accepted comment-author
prefix on each actual local core, rather than treating actor names or counters
as proof. The current inventory's registrations must agree with those bindings.

`kind: 'checked'` requires exact accepted native heads, complete registered-stream
coverage, current local review progress, no outstanding publication/decision/
revision intent in any selected source's metadata records, complete metadata
dependencies, and a complete current provider byte set. A published suggestion
may remain undecided: publishing the proposal does not accept it into the
document. Intentionally local packets are retained without inventing publication
intent. Pending native suffixes remain pending and are never acknowledged by a
read.

`kind: 'pending'` retains explicit head relations, registration gaps, local review
progress gaps, metadata queue operations, unresolved references and provider
requirements. Head vectors use the original report's canonical author ordering.
Report collection shares the existing 100,000-requirement ceiling and fails at
the bound without large argument spreads or truncating required work.

The result contains the literal original diagnostic as `legacy`, the complete
asset/reference bundle as `assets`, separately proved local `reviews`, and the
pending requirements. It is immutable data. Original wire formats, defaults,
native histories, packets, decisions and upload receipts remain unchanged.

An original version catalog also has a constructor-owned retention check. Its
ordinary editing guard continues to reject while a native delivery loan owns
the catalog. That temporary exclusion must not make the containing retained
source look disposed to the loan's own authority callback. The retention check
therefore distinguishes an actual constructor-owned native borrow from ordinary
backup/recovery work, while checking the exact catalog/store/core bindings,
store lease, closing and retirement state. Copies cannot provide this check;

The original parent's retained callback uses that same constructor-owned check,
while still checking its unchanged lifetime, all held recovery leases, session,
suggestion and revision owners, and upload store. Ordinary recovery handoff
continues to use its original editing exclusion. Direct child and parent tests

## Upload, refresh and resume

the V2 local/provider byte union. It remains unacknowledged until a real upload.
After closing the finite metadata/review scope, use the retained owner's managed
asset ports to flush through the actual authenticated uploader. Each real store

That upload can change the exact server selection. Refresh the actual native

existing journals and older complete bundle. The old immutable bundle retains
its original pending states and bytes. It neither overwrites later stored facts

Delivery then uses the original adapters for every source family: the actual

catalog dependencies require actual authenticated packet loads before complete
reference capture; catalog entries alone are insufficient.

## Remaining release boundaries

This read inspects the current retained outbound records; it does not establish
that every remote discovery catalog or historical packet has been downloaded.
Complete remote metadata closure remains separate work. The current inventory
provides metadata binding IDs rather than exact current catalog/receipt contents.
This check therefore does not establish current server containment of locally
retained metadata receipts. A genuine current server catalog check must precede
whole-room activation. It also does not restore
a backend, recover protected credentials, retire or transfer native actors,
commit a deployment epoch, grant a serving lease or activate a whole room.
Those transitions require actual native owners, fresh authentication and the
common ownership barrier, with the complete reconciled files retained first.
