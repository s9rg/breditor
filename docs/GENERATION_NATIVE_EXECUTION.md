# Durable generation native execution

The selected generation executor retains complete native recovery inputs and
append-only progress before admitting accepted server operations to actual client
cores. It is a private functional recovery route, not a delivery acknowledgement
or permission to activate a room. Original physical recovery and native packet
formats retain their existing meanings.

## Separate generation inputs and ownership

The input coordinator requires a genuine SharedServerLogGenerationRecoveryHost
before inspecting incoming read factories or decision options. The control binds
the actual origin, current server and participant inventory. No physical ancestor,
localOrigin alias or saved report substitutes that selection.

The selected-generation-native-import family has its own revision-one magic,
MIME type, manifest, selection, choice and retained-input records. It stores the
complete selected before-file and every original request-bound accepted page.
Admission validates exact lengths, hashes, canonical headers and a terminating
cursor chain. Physical and generation archives or stores cannot substitute for
one another, including when the underlying table geometry is the same.

Preparation changes no native client. Retention uses absent-only creation or an
exact read-only retry under fresh approval. Existing-only cold opening aborts an
absent database rather than publishing a placeholder. The retained input class
owns its actual namespace, connection and lease. Public methods, copied data and
outside hashes cannot manufacture that custody.

The preparation grant and signal expire after retention. Fresh storage
verification needs fresh permission; it does not revive editing rights or
authenticate the source server. Retained immutable bytes remain data, not rights.
Neither input nor executor is exported by the default package root.

## Authentication before admission

Every execution or resume reissues each original request to the independently
pinned live generation host. The complete stored response must match the fresh
accepted response. Only the authenticated reader's current review role is omitted
from historical comparison; it never becomes a recipient's permission. Original
review sources and retained native receipts remain verified.

An input with valid hashes and a genuine retained-input owner can still contain
unauthenticated data. Such a payload refuses before approval, journal creation or
native admission. Missing own accepted prefixes, unknown own suffixes and native
forks require explicit reconciliation, not a text-equality shortcut. Local
comment lanes stay unbound and their original histories remain intact.

## Durable progress before native changes

The selected-generation-native-execution family has separate revision-one
identity, intent, event and result records, with separate start and resume
decision choices. The initial intent, complete input and before-cut commit in
one absent-only transaction before the first native publication. The exact
selected client set is retained with that intent.

Each actual recipient imports the original native document and eligible bound
comment pages under the common native reservation. Its complete extending source,
native, packet and upload cut is then appended as immutable progress. Metadata
compare-and-swap and complete hash readback reject stale or copied witnesses.
An interrupted append preserves any committed evidence without repairing or
overwriting earlier records.

An error before admission leaves clients usable. After any admission attempt,
uncertain execution retires every actual client before common exclusion is
released. Real namespace and lock cleanup acknowledgements remain required;
prepared stages or caller flags cannot substitute for cleanup.

## Cold resume and later offline work

Resume opens the actual existing journal, re-admits its complete input and checks
every saved before, client and resume cut against one actual current source cut.
It requires a new affirmative decision at the exact saved head and current cut.
The new resume before-cut commits before replay.

All original pages replay even after a saved read stage. Compatible later own
edits and native Undo/Redo must survive a completed recovery, new offline work
and a later source reopen. Bound comments import using their historical verified
source, while local comments remain unbound. No native import settles queued
suggestions, revisions, versions or upload delivery receipts.

Stored read evidence is diagnostic data, not an authenticated execution-complete
or serving decision. A local-ahead requirement remains outstanding work. The
native/source before-files and all original input bytes remain available for
separate reconstruction or conflict decisions.

## Bounds and remaining integration

Inputs and journals retain their explicit one-GiB limits, 4,096 pages or events,
and existing native frame/source limits. They refuse overflow without truncating
history. These are bounded recovery lifetimes, not sustainable-history closure.

The selected host cut must still match the retained input exactly. The separate
[generation reconstruction route](GENERATION_NATIVE_RECONSTRUCTION.md) now covers
older source state wholly contained in the last retained output, without weakening
ordinary resume. Mixed ahead/behind source frontiers, a server that has advanced
to a different cut and conflicting historical packet copies still need their
explicit reconstruction and reconciliation joins. Explicit local-comment adoption, authenticated old-serving
exclusion and a durable whole-room activation decision remain required. All
thirteen V1 release gates and the full feature-parity objective remain open.

Functional verification covers real generation controls and native payloads,
all ten grammar/writer-transport input configurations, all four independent
document/comment history pairs across seven source families, storage faults,
page reauthentication and genuine cold resume. Fresh installed packages and
actual production bundles run the same assertions with location-only fixture
rewrites. Node storage, locks and raster presentation are controlled fixtures,
not physical crash durability or browser certification.
