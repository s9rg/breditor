or whole-room activation API. Original preparation, journal v1 events, native

## Real ownership, not stored permission

The host first genuinely reopens source parents and reconstructs a selected owner
from complete persisted files. The journal does not do that from an actor ID,
old token or saved approval. A new retained-native delivery scope must own all
actual cores, source IO and upload resources. Old gates remain permanently closed.

previewSelectedNativeDeliveryJournalResume returns detached DATA. It opens both
existing-only namespaces and re-admits the immutable original before-file and
every saved client, native server and participant-inventory file. A missing
journal/preparation upgrade aborts; no empty placeholder or new baseline is made.

SelectedNativeDeliveryJournal.resume requires an independently selected choice
and a fresh asynchronous approve callback for this attempt. Cheap genuine-scope
and private operator/reader brands precede authority callbacks. All inputs and
intrinsics are captured before callbacks; copying their public methods grants
nothing. The new choice contains the literal journal identity/head, complete
current client selection and authenticated complete native path control selection.

Both inspections around approval perform complete native/source/packet/whole-
upload continuation checks for EVERY saved cut, current provider reconciliation,
fresh native path and latest-predecessor checks, fresh full journal loads and
actual current-source equality fences. A native path may retain additional
observed cuts, but every saved server cut must occur in order and with multiplicity.
No-op checkpoints are not deduplicated. The baseline checker still names B; the
latest-predecessor checker must name the final saved server cut. All current
operator controls must refer to the same A/D/participants.

Only successful inspection and THIS fresh decision create a one-use, same-scope
runtime admission held in a private WeakMap. Neither decoded JSON nor an earlier
gate can create or replay it. The admission opens a genuinely new context/drain
owner around the original immutable preparation file. Before any adapter is
admitted, a new factual checkpoint records the actual cold-opened current owner.
All prior events/files stay literal. Subsequent delivery remains one source per
successful checkpoint and uses real authenticated document/comment adapters.

## Resume across a sealed handover

A changed restore origin requires
`previewSelectedNativeDeliveryJournalHandover` and
`SelectedNativeDeliveryJournal.resumeAcrossHandover`. Use a fresh
`SharedServerLogGenerationDeliveryPathRecoveryHost.openHandover` checker and
readers for the actual successor archive and participant inventory. The
authenticated path must include the original catalog cuts and every saved
server cut in order, including repeated observations. A successor-local
checker alone cannot reopen the earlier journal.

The preview binds the literal journal head and current client selection to the
sealed handover. A fresh decision and a complete recheck admit a new delivery
owner. It appends a distinct handover event and preserves the earlier events
and files byte for byte. Record later delivery cuts with
`recordAcrossHandover` and a freshly provisioned path. The append transaction
compares every old row and byte against the inspected snapshot before writing.
Normal document and comment adapters still submit operations and receive
acknowledgements through their existing protocols.

## Cancellation and failure

Initialization and cleanup are registered with the genuine parent before their
first await. Close tracks real opening/read/append work and adapter drain, then
releases actual IndexedDB requests, namespace custody and WebLocks. Policy loss,
stale pins, changed old bytes, disposed/foreign readers or failed native checks
refuse admission. A committed checkpoint that is refused afterward is preserved;
it is never erased or mistaken for permission. Missing or uncertain cleanup
cannot be declared complete from a canceled facade promise.

A fresh policy refusal at the one-shot admission-to-gate boundary must also
finish actual preparation cleanup before rejecting. Token consumption itself
is callback-free; every subsequent check and parent registration runs inside
the gate factory's owned cleanup. If claiming the newly created gate fails,
the journal waits for that gate's real close as well. Restoring policy may then
retry the namespace, but cannot reuse the consumed admission or release the
outer native exclusion. This was reproduced with a genuine approved admission,
not an object-shaped token, and has its own required native/installed regression.

The journal still refuses 4,096 entries or 2 GiB rather than trimming history.
Repeated complete archive/native materialization is intentionally conservative;
large/long-lived session performance remains unqualified.
