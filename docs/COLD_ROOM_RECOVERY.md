# Fresh actor recovery for complete saved rooms

The private cold recovery attempt reopens a complete existing selected room using
fresh document and comment writer locks. It needs no surviving editor or warm
actor cohort. A retained basis selects the room and its namespaces; admission
then verifies actual current native histories, dependent packets and complete
upload queues. Newer uncaptured work stays in place instead of being restored
over from that basis. The result is local ownership, not server activation.

## Data before fresh locks

Construction is synchronous and performs no I/O. The caller receives the attempt
before it can acquire a lock or open a mutable source. All input records are
detached, own-data snapshots. The complete independently pinned basis must agree
with the supplied root database, catalog namespace and catalog selection. A
canonical preflight checks every source family, namespace and actor identity
before any writer request. Executable participant policies are fresh host input,
not permissions restored from saved data.

The actor acquisition object also exists before its first asynchronous request.
It retains each actual returned document or comment lease before checking
cancellation or permission again. If a later writer is occupied, the same object
keeps its earlier leases and can retry after that blocker closes. A partial set,
a ready report or a prototype-shaped object cannot become a cohort. The SDK
transfers only a complete genuine set through a synchronous private reservation.

## Current state rather than a restored snapshot

After fresh acquisition the attempt reopens the existing root with the genuine
cohort and finishes its normal child admission. The ordinary cold-selected
coordinator still verifies approval-to-retained and retained-to-actual-current
native ancestry, dependent packet continuity and every selected upload queue.
Preview returns the actual current cut. It creates no approval or replacement.

Promotion rechecks that complete current choice and requests a fresh decision.
The existing cold intent stores both complete basis and current files atomically;
an aborted transaction cannot publish a partial intent. An exact saved intent
resolves an uncertain write, but it does not replace the next decision or current
participant grants. Original intent schemas and ordinary cold defaults remain
unchanged.

The final move uses the existing common native, packet, parent and selected-asset
barrier plus the actual actor cohort. An already-owned inactive recipient holds
the successor before any ownership flag changes. After the synchronous barrier,
one synchronous take ends the finite read job and transfers the live owner.
Native document/comment Undo and Redo, outstanding offline edits, later upload
receipts and new pending uploads remain usable under independent current grants.

## Cleanup owns real resources

Take reserves the actual pointer move before ending the read job, because that
cleanup can fire synchronous abort observers. A nested take refuses as busy. If
a callback instead requests Close, take rechecks cancellation before moving the
reference and leaves the owner reachable in its recipient for real cleanup.

Close publishes its actual cleanup Promise before firing synchronous abort
observers. Reentrant Close calls join that exact operation. Cleanup waits for
real pending acquisitions, closes the actual returned or staged resources, drains
failed openings, and only then releases actor custody. A rejected cleanup keeps
its handles reachable for retry. Cleanup does not need continuing read permission
and never deletes source, target, journal, approval or upload bytes.

## Inspect without repairing

The explicit private [completed room inspection](COMPLETE_EXISTING_ROOM_INSPECTION.md)
entry uses the same fresh actor and attempt lifetime but refuses incomplete
parents and pending native saves instead of continuing them. Ordinary cold
recovery retains its repair-capable defaults. Use the stricter path when checking
an original before building a replacement; invoke repair as a separate decision.

## Remaining architectural work

This path requires a complete existing selected root and an independently kept
basis. Interrupted replacement execution before that root exists still needs a
separate cold execution contract; a saved warm retirement marker must not be
reinterpreted as fresh actor ownership. Physical crash durability also remains
separate from the controlled storage and lock tests.

Native author union and provider/client reconciliation, independent comment and
server-log generations, authenticated whole-room activation and sustainable
retention across Undo, offline work and assets remain on the full parity goal.
The package root exports no new recovery or activation grant. All thirteen V1
release gates remain open.
