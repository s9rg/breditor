# Restored local operational participant

The private restored-local participant coordinates the literal incoming portable
archive, native journal/source and whole upload store. Its first source publishes
verified input LIVE once; earlier cuts remain provenance. A real upload lease
stays held through the final native/policy comparison and source handoff. This
does not implement room activation or repeated flat provenance export.

## Current host contract

`RestoredLocalParticipantOptions` requires the existing journal/source names and
an explicit cohort containing distinct parent and upload namespaces. The host
selects current native factories, document/comment permissions, cancellation and
reacquired writer authority. Saved files grant none of those permissions.
Runtime opening custody reserves all four names before authority callbacks. Only
a genuine opening in that exact context/cohort may delegate its native pair or
upload subset; serialized readiness flags and retired openings cannot do so.

Actual namespace leases, both native writer leases and cooperative whole-upload
exclusion protect the admitted owners. These are current-SDK ownership rules,
not distributed server authorization or physical crash-durability certification.
Older local/delivery formats, readers and public root exports remain closed.

## Durable parent phases

The separate parent schema retains its literal input and an exact phase record.
The plan binds the selected input operation/file digest and all four destinations.
Transitions compare the entire prior record; input bytes are checked separately
against their admitted size, type and digest.

- Preparing retains the input while admitting the journal and original whole
  uploads. Only this phase may initialize an absent or empty partial upload store.
- Prepared acknowledges those baselines before the actual source opens. Its first
  native cut can be absent, pending or acknowledged after an interrupted save.
- Operational requires an acknowledged native journal cut and actual retained
  source/upload storage. Missing acknowledged components refuse before native
  initialization; an operational flag cannot recreate them from imported LIVE.

Initial parent-schema cancellation requires an explicit new begin with the input;
it is not counted as a durable cold recovery. Later aborted or committed-but-lost
completion states resume only from the actual retained phases and cuts. No old
input, pending work or competing destination is overwritten.

## Native and upload conservation

The source owns its separate incoming archive and read-only LIVE ancestry anchor.
Current/pending native cuts continue that input in both histories, with unique
ordered versions. Complete upload data is restored without retrying jobs or
starting network work. Ordinary local blob/data raster reads remain admission,
not network upload or server activation.

Original rows retain pixel identity, MIME type, dimensions, byte length and
monotone attempts/epochs. Uploaded receipts cannot be replaced. Provider-only
pixels stay with the source-owned archive rather than becoming new upload jobs.
The upload owner and native journal must bind the same actual input operation.

## Exact handoff and cleanup

`intoParts()` returns the genuine source, original upload-store handle and an
input provider. Its source type preserves the selected Rust selection policy.
`input.file()` is literal imported provenance, not a new backup of later edits.
Previously obtained Blob values remain caller-owned data.

The native witness and upload exclusion survive awaited namespace releases,
retained-record checks, parent-wrapper disposal and handle closure. Each final
authority callback precedes exact native value/stamp checks. A changed document
or comment publication refuses the handoff. No callback or await follows the
final native comparison and synchronous upload release.

The same returned upload handle waits for its real release callback before later
mutations; a foreign handle can briefly report Busy during that completion.
Denied handoff keeps actual owners for retry, even after parent wrappers or
handles close. Retry reopens retained handles only. Cleanup waits for actual
native/upload callbacks and retries the same owners instead of recreating a
disposed native editor. The source/provider lifetime never captures parent-closed
state, so editing and saving continue after parent retirement.

## Independent read execution policy

Borrowed journal reads use fresh synchronous authority and cancellation. They
may explicitly select a current matching read-only factory, snapshotted after
scope reservation and before authority callbacks. A retired writer factory need
not be reused. Getter reentry remains within the bounded read-scope budget.

A fresh reader reconstructs its own LIVE anchor from exact owned native data.
Current/pending ancestry comparisons stay within that runtime instance; old
native pointers never cross into a different Wasm instance. Temporary owners are
freed before the final fresh policy check. Reading opens no persistent author and
does not infer permission from a matching hash or native history.

## Remaining closure

The [flat-provenance contract](FLAT_LOCAL_OPERATION_PROVENANCE.md) must preserve
every incoming original/CURRENT/PENDING/LIVE cut,
later native work, whole uploads and historical provider-only pixels in a bounded
flat graph. Resetting the origin or recursively nesting opaque operation archives
does not satisfy that requirement. Actual five-family room adoption, complete
historic-copy/provider/client reconciliation and authenticated activation remain
separate work. Sustainable native Undo/offline retention and all V1 parity and
release gates remain open.
