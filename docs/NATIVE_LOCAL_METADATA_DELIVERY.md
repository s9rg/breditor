# Native local metadata delivery

This private contract adds explicit metadata binding, complete cold continuation
and non-overwriting metadata DATA restore for the three independent local source
families. Verification is recorded separately; the thirteen V1/parity gates remain
open. This layer alone cannot activate a room or establish release readiness.

The metadata owner borrows the genuine opened local-review delivery owner. It
uses that parent's one prepared gate, original independent-history sessions and
current native recovery scope. A saved choice, structural copy, matching writer
ID or application save callback cannot supply those resources. The three source
families keep their original local history formats and policies.

A separate closed metadata envelope pins all selected local lanes, their exact
nonsecret retained bindings and a digest of each original initial record. Initial
binding can carry captured local proposal, revision and version packets. It cannot
assert server publication, final decisions, accepted effects or discovery feeds.
Native admission verifies each original packet against its recorded source point;
current server authority comes separately from the original SDK transports.

The original version catalog, suggestion queue and revision outbox open as dormant
source-owned children. Their records stage into one additional journal through
their existing native held-work mechanisms. Each actual write saves the original
paired source first, then atomically retains the complete metadata cut through
an exact-byte compare-and-swap. Original packets and settled receipts cannot
disappear during continuation. The initial record is immutable.

The journal remembers a completed transaction before a later authority check can
refuse. A storage failure retains its previous committed record. A post-commit
refusal keeps the actual newer fact and supplies no permission to continue delivery.
Explicit retry uses the original SDK queue, outbox, catalog and exact packets.
Closing temporary metadata children never deletes the journal, initial intent,
native histories, saved versions or uploads.

The parent publishes a child opening slot before application callbacks. Parent
close stops the child and waits for actual opening, writes, adapters and coupled
capture work. Parent capture cannot return a review-only bundle after metadata
has been enlisted, including after the metadata facade closes. Coupled capture
keeps parent quiescence through both journals and the metadata digest, so a new
context cannot advance a source between the two exported parts.

The new complete bundle contains the literal original local-review bundle and
the additional metadata snapshot. Raw Blob lengths and SHA-256 digests are checked
before decoding; canonical JSON is checked separately. Its current native/relay
rows must exactly match the parent bundle's current rows. Older room, history and
review readers stay closed and do not implicitly accept this envelope.

Cold preview requires the genuine fresh parent and existing metadata namespace.
The decision pins the complete portable multipart identity plus the actual stored
metadata revision, length and SHA-256. A later committed stored head can continue
an older complete export; it is never replaced by that older file. Both keep the
same original initial record and bindings. Native replay must prove the initial
cut precedes the portable current cut and that the portable cut precedes the
stored head, with complete document/comment histories and retained versions.
Packets and receipts are admitted at their own recorded native points. Sharing
a live descendant or matching final text does not prove this order.

Reopen obtains a fresh explicit approval and repeats native and stored-head
inspection afterward. A changed head refuses the old decision. Reopen creates a
new current metadata owner; it does not revive old callbacks, tokens or transport.
All connections still require separate original authenticated SDK operations.

Metadata DATA restore is a separate closed operation under the genuine current
parent. It checks the complete bundle and native order, pins the current room and
observed destination, and repeats inspection after approval. An absent destination
gets exactly the original initial and advanced current strings. A byte-identical
destination permits a no-write retry. Any different data, schema or extra rows
refuses without overwrite. Read probes abort upgrades and create no placeholder.
The two-string physical copier is reused without admitting metadata through any
older review protocol parser. Committed data survives subsequent permission loss.
Late actual requests retain namespace custody until cleanup really finishes.

Restore returns DATA only: no actors, sockets, metadata runtime or activation.
Reopening restored data requires a separate fresh metadata resume decision under
the current parent. No initial seed, Undo history or outstanding edit is reset.

Mandatory candidate checks cover the closed contracts, strict types, physical
storage failures, the actual seven-family native relay/cold/restore workflow and
the same workflow from independently packed, offline-installed npm archives.
Node IndexedDB and WebLocks are controlled fixtures; native replay and original
authenticated relay receipts are real. Physical browser durability is separate.

The broader V1 work still requires complete provider/client/historical-copy and
asset reconciliation, including assets referenced by these added immutable
metadata packets, followed by authenticated joint activation. Original public
exports, package versions, protocol meanings, default behavior and normal Wasm
are unchanged. Input/accessibility and performance remain separate release checks.
