# Local-only native origins before autosave

The private `IndependentLocalNativeOperationOrigin` proves that both native
histories continue from an independently selected complete local participant.
It does not manufacture a delivery companion, binding, receipt or completed
recovery marker. Ordinary independent-history APIs, native formats, local source
classification and the `history_files`/`history_heads` schema remain unchanged.

This is a prerequisite for local operational provenance and five-family room
staging, not their completion. It does not durably retain an original/current/
pending operation journal, reconcile providers or authorize server activation.

## Genuine immutable origin and independent current policy

The host selects a genuine `SharedIndependentParticipantBackup`, its exact
expected identity/digest, explicit read-only native factories, a synchronous
current-authority check and optional actual cancellation signal. Inputs,
generation options and complete native policy identities are snapshotted before
the first authority callback. The file cannot choose factories or a current grant.

Canonical archive methods read the actual file and native recovery; a prepared
DTO's checkpoint fields are never trusted. The origin replays the original or
segmented document and independently selected comment history in a private
read-only editor. Replay acquires neither native author lease. Both checkpoints
must equal the selected originals, and every retained version packet must pass
actual native admission. Failure frees the unreturned native owner.

The origin borrows the backup for its lifetime. It neither disposes that backup
nor moves its original-only raster bytes into the upload queue. A future parent
must co-own the original provider, source and whole upload store. Losing the
borrowed backup prevents persistence; it does not hide the live source's readable
unsaved recovery.

## Actual local-source persistence policy

The separately named private open/restore functions issue a genuine WeakMap-bound
native policy after snapshotting current factories, native identities and access.
Serialized fields and fake origins cannot issue it. The policy is separate from
the lower source's delivery/storage companion; an already selected incompatible
companion refuses before any destination is opened. Existing private bootstrap
checks are explicitly forwarded, not silently erased by the option snapshot.

Origin/current checks run before author acquisition, after asynchronous opening
boundaries and before constructor autosave. Actual Rust original/segmented
ancestry checks cover both lanes, not AST or head-hash equality. Original local
version packets cannot disappear; legitimate later versions may be appended.

Unlike the temporary recovery-bootstrap policy, this native policy remains for
the source lifetime. Every persistence capture verifies ancestry and versions.
Current checks also run at the real paired transaction callbacks. An explicitly
selected lifetime signal subscribes to each actual write transaction, including
the interval after a head request succeeds but before transaction completion.
An observed abort while that transaction is active aborts its writes. When both
temporary and lifetime signals are selected, both actual signals subscribe to
the first save. Neither replaces the other. Listeners detach on completion/abort;
no listener is added to ordinary unselected sources.

Post-commit refusal cannot roll back a completed transaction. The existing exact
attempt and lost-acknowledgement rules retain its bytes; retry acknowledges them
without rewriting immutable native files. Refusal never silently repairs or
replaces a committed cut.

## Readable work and lifetime

Source export remains local-only and readable after loss of the origin, write
grant or signal. It is data, not permission to resume writing or connect. A
separate private readable ancestry capability can be used under independently
authorized read policy while the genuine origin and borrowed archive remain
live; it does not grant persistence.

Disposing the origin blocks future selected saves but does not dispose the
borrowed live source or original provider. Closing a source retains its normal
save-first behavior. Explicit discard closes unsaved memory and writer leases
without deleting the durable data. Native factory failures release their actual
unreturned owners, so fresh explicit retries can reacquire the author.

## Required checks and remaining scope

Both candidate profiles require focused local-origin laws, strict public-export
fences and fixed source/fresh-installed matrices. The domain is five native
compiler profiles, three selection scopes, all eight capability masks and all
four independent document/comment history pairs: 480 cases, without substituted
runtimes or a reduced smoke domain. Assertions cover exact editable/read-only
cold replay, future Undo/Redo after offline peer work, append-only versions,
local-only source capture, delivery-family refusal and original-provider lifetime.

Controlled IndexedDB, locks and PNG presentation do not establish physical
durability, production memory/latency envelopes or browser support. No native
code is changed, no sustainable history ceiling is lifted and no historic copy
is discarded. Complete local operation journaling, actual five-family native
staging/adoption, provider/client closure and authenticated activation remain
required. This private prerequisite is not V1 or feature-parity approval.

## Selected functional qualification

The [2026-10-22 qualification](qualification/2026-10-22-independent-local-native-origin.json)
passes 39 selected checks from the 308-check plan. Source and fresh offline
packages each pass 37 focused laws and all 480 native cases. Each matrix performs
960 editable/read-only cold opens, 1,440 future document/comment history
comparisons, 480 later-version appends and 960 local-only source captures. It
also checks 960 delivery-family refusals and preserves every original provider
after the origin is disposed. Local operation admission starts zero network work.

Four extra composition laws exposed three failures in the development
implementation: incompatible companion selection or temporary bootstrap policy
could disappear during option copying, and bootstrap cancellation could be lost.
The same assertions pass unchanged after explicit forwarding/refusal and both
actual transaction subscriptions. An isolated rebuild of a fresh consumer with
only the three recorded earlier policy files reproduces all three failures.
Neither the control nor the earlier development foundation run qualifies a
historical released package or replaces the final fixed-source evidence.

Six actual consumers pin matching archives. Existing source/installed native
delivery origins pass 640 cases each, complete local recovery 240 each, and
local capture 80 each. Full delivery recovery passes 256 cuts and 512 handoffs
per matrix with 131 focused laws. Workspace/diagnostic tests pass 2,647, editor
tests 385 and scripts 2,520, with three existing opt-in browser skips.

All twelve normal runtime files and 2,857 Rust/manifest inputs remain unchanged;
full Rust suites are not freshly run. Catalog contracts pass freshly, but its
two full catalog matrices are carried across nine unchanged data-reader files,
not relabeled as fresh here. Actual parent/source/provider lifetime ownership,
namespace/context custody, five-family native staging/adoption and authenticated
activation remain separate integrations. Native proof alone cannot mint them.
