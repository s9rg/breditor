# Fresh protected-history read barrier

`reserveProtectedOperationalHistoryRead` synchronously reserves genuine original
and generation operational parents before the first fresh permission or
cancellation callback. `prepare()` then reads protected archives and all actual
current native/packet states through the explicit historical-reference scope.
This private barrier is not yet the seven-family room reconciliation API.

## Reservation is not handoff

Admission checks private class brands, distinct owners and IDs, closed data
properties and explicit native read factories. Caller iterators, array/row field
getters, mutable source selectors and family-tag substitutions cannot manufacture
custody. Both family reservations are established before any read hook runs.
Their transfer verification, consumption, retirement and lease-release operations
are never invoked. Cleanup uses only read disposal and reservation abandonment.

Fresh permission and cancellation are independent of expired original job grants
or cancellation. Reading cannot reactivate those jobs. Actual parent, source and
whole-upload custody remain held after the read closes. Each current source is
selected by the SDK; the result exposes no editable producer or individual child
unlock path. Multiple original parents retain separate catalog/queue gates.

## One held result

`verify()` rechecks actual member archives and source records. The final
callback-free fence compares every selected member after all host callbacks and
after metadata construction. A late callback changing an earlier source invalidates
the whole result. `checkCurrent()` does not inspect out-of-band stored bytes by
itself; those require verification.

Failed preparation closes every partial read and reservation without consuming a
parent. Cleanup retains callbacks until it succeeds, permitting retry. Closed
prepared reports keep immutable detached metadata while releasing read permission,
restore factories and producer callbacks. Closing an unprepared reservation does
not construct a report. No state authorizes activation or provider access.

## Explicit limits

The input contains one to 1,024 parents. The sum of per-participant reference
unions is limited to 100,000 entries, counting repeated addresses in different
participants separately. The sum of UTF-8 JSON history-metadata payloads is
limited to 64 MiB, excluding the separately bounded outer IDs/framing. Existing
per-replay native packet and reference limits still apply. A limit refusal returns
no partial ready report and never truncates or rewrites retained user data.
