# Native local participant cohort

Snapshot and flat-local operational parents can hand off their actual native
writers and complete upload stores together. They use the existing room handoff
kernel; they do not activate a room or reconcile its other retained copies.

## Genuine reservations before callbacks

The private router accepts distinct IDs and the two explicitly named families.
It reads a bounded indexed array before reserving owners. Caller traversal hooks
cannot omit members, sparse arrays refuse, and saved readiness objects cannot
supply a parent. The selected native document policy remains in the source type.

Every genuine parent becomes busy synchronously before verification can call
host code. Each parent independently checks its retained input, phase, native
source, upload baseline and actual storage context. Coordinator leases and
temporary input wrappers can close during preparation; native writer leases,
source journals and genuine upload exclusion remain held.

These upload stores already have actual custody. The shared kernel does not try
to acquire the same exclusive leases a second time. Each member's final witness
still checks those exact held owners. No readiness flag replaces that custody.

## One final transfer barrier

Result wrappers are constructed while closed. The kernel runs current-policy
checks and auxiliary cleanup before its final callback-free native/storage pass.
A late callback that edits an earlier document or comment history, including a
generation seal, refuses the entire transfer. The same fence works when the two
families belong to separately reserved groups in the shared kernel.

Only after every member passes are uploads released and parent flags consumed,
without a new wrapper construction, authority callback or await. A denied grant,
failed wrapper construction or asynchronous namespace-release failure returns
no parts and keeps all actual owners reachable for a fresh attempt.

Returned sources retain their selected original or segmented histories, version
catalogs, input providers and journal ownership. Closing retired parent objects
does not close those sources. Original input files remain provenance, not a new
backup of later edits; independently held Blob values remain caller-owned data.

## Publication while opening

The snapshot parent, witness and upload owner stay unexposed while constructors
and admission checks run. Their public operations refuse during construction.
The parent rechecks current native state and policy after construction before
publishing itself. Interrupted openings retain their real durable phases for
explicit recovery rather than exposing partly validated owners.

## Scope

The in-process cohort supports at most 1,024 members. It adds no serialized
protocol, public package-root export, default storage choice or native runtime.
Normal component limits and storage requirements remain unchanged.

The fixed new workload covers ten two-writer cohorts, all four document/comment
history pairs, both family orders and homogeneous groups under the normal
language-three profile. It preserves forty handoffs, complete native records,
uploads, literal inputs and provider pixels, with twenty cold continuations,
later edits, versions and document/comment Undo/Redo exercises. It is not a full
Cartesian native-profile or policy matrix.

Full seven-family physical catalog adoption, complete retained-copy and live
provider/client reconciliation, authenticated activation and sustainable native
history remain separate requirements. Synthetic storage does not qualify
physical durability. All V1 release gates remain open.
